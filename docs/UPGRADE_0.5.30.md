# 0.5.30：独立成员连接与分镜流程权限

在 0.5.29 上增加可选的成员身份模式，解决员工各用自己的 ChatGPT、却共用 Google 授权时，旧服务按相同 OAuth subject 识别为同一管理员的问题。

## 发布内容

- 每位成员使用经过 Auth0 confidential client 配置核验的独立连接凭据；服务器验证签名 token 的 issuer、audience、client、Google subject 和签发时间，再查找成员。
- Admin / Producer 与项目空间绑定成员 ID，员工未登记、停用、凭据不匹配或成员清单无效时拒绝访问。旧 Google subject 管理员授权在成员模式中不生效。
- 员工可修改分镜内容，不能修改流程规则、审核门禁、模板结构或程序配置；继续使用原有 24 / 21 个工具目录及服务端权限检查。
- 管理员可显式保留历史项目空间；旧项目、持久卷、签名密钥和 Library 指针不删除、不自动复制给员工。

## 代码部署与成员切换

代码可先部署，默认 `SHORTDRAMA_MEMBER_CONNECTION_ACCESS=0`，此时保留现有认证行为。**这一步不会降低共用管理员授权的员工权限。**

随后按[成员连接方案](member-connections.md)核验 Auth0 客户端，准备管理员与员工的独立连接，安装成员清单并启用模式。启用后，未登记的旧连接被拒绝；员工须使用分配给自己的连接凭据重新授权。管理员保留旧项目的访问能力后，再停用或撤销旧共享连接。不要只反复用同一个 Google 登录旧连接，也不要在新管理员连接未验收前删除旧认证配置。

服务器已存在成员清单时，关闭模式会使新代码拒绝启动，避免意外退回共享 Google 管理员模式。恢复部署应保留经验证的成员清单与兼容代码。

## 验证要求

发布前运行完整 Linux CI、运行时与 HTTP / stdio 检查、规则注册表一致性和包检查。真实员工接入还需分别验证管理员旧项目、员工内容操作、规则修改拒绝、跨成员访问拒绝、真实 token 续期和停用生效。

本地测试结果见[验证记录](member-connections-validation.md)。代码检查、生产部署和员工接入是不同验收状态；不据此承诺 10 人重任务吞吐或分镜语义质量。
