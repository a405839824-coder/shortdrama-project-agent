# 0.5.17：眼部表演硬门禁与相邻镜头全覆盖审计

0.5.17 把“自然眼神与眨眼”和“相邻镜头连续性”从写作建议升级为可执行、可拒绝、可复算并写入证书身份的生产与独立审计契约。现有分镜、XLSX、canonical、交接、证书与台账保持不可变；历史 v1/v2 独审记录可读，但不能为当前写入放行或命中当前审计缓存。

## THG-13：眼部表演链

面部清晰可见且持续至少 2 秒的镜头必须在 `画面内容` 时间轴中写明：

1. 视线或眼球的起点与目标；
2. 轻微眼球换焦、位移或焦点调整；
3. 眼球先动、头部随后轻跟，或明确头部保持不动；
4. 上/下眼睑松紧变化；
5. 与开口前、换焦、听后反应、换气或镜尾绑定的明确眨眼次数，或有高压、震惊、认出、警觉、关键词/重音等剧情理由的不眨眼；
6. 不眨眼时必须保留眼球焦点、眼睑和自然呼吸三类替代动态；
7. 镜尾阶段的最终视线落点。

有对白时，关键词、重音或决定性尾音期间明确不眨眼。多人清晰同框时，眨眼和反应必须错峰，不同时闭眼。`生成限制`同时要求眼神自然聚焦、轻微换焦、眼睑变化，并禁止无依据全程不眨眼、僵直瞪视、高频机械眨眼和多人同步眨眼。

静态 GPT 关键帧不描述眨眼过程，只声明双眼自然睁开并避开半眨眼/半闭眼瞬间；只有权威原文明确要求闭眼、睡着或昏迷时才允许闭眼状态。

## THG-14：N−1 相邻镜头逐组连续性证明

对一个按 canonical 顺序包含 N 个镜头的项目，生产验证器必须精确枚举 N−1 个有序相邻对。每对固定审查：

- 人物位置；
- 身体朝向；
- 视线落点；
- 手持道具；
- 门窗状态；
- 动作进度；
- 光源方向。

`prevention_evidence.adjacent_continuity_audit` 保存契约名、期望/已审数量、100% 覆盖率、有序 pair 列表 SHA-256，以及每一对的左右镜头 ID、边界类型、左镜尾/右镜头状态哈希、已审字段、连续结论和转场解释。同场景必须状态闭合；跨场或跨集必须有可观察、可审计的边界解释。

少一对、重复、逆序、乱序、非相邻引用、状态哈希漂移、字段缺失、覆盖率低于 100%，或跨场/跨集无解释，均产生 `E-CONTINUITY-001 / THG-14` 并阻止提交或签证。增量修改后由服务端确定性重建该全局证明，调用方不能用陈旧证明绕过受影响边界。

## 独立审计 v3

当前契约为 `semantic-audit-v3-adjacent-continuity`。首次或指纹变化后的独立审计必须提交：

- 精确 canonical SHA-256；
- 精确镜头数；
- `reviewed_adjacent_pair_count=N−1`；
- canonical 有序 pair ID 数组的 SHA-256；
- 八个唯一语义审计层。

“空间连续”层必须按 canonical 顺序且恰好一次提交全部 `pair:左镜->右镜`；绑定 pair 的问题必须只指向这两个镜头并保持左到右顺序。“表演链”层复核 THG-13。服务端将提交内容与当前验证器重新生成的 N−1 机器清单交叉校验，二者任一不完整都不签发证书。

新证书、独立证据矩阵和缓存身份均绑定相邻对数量、顺序哈希与 v3 契约。旧 `semantic-audit-v2-compact-master` 仅保留历史可读性，不可复用为 0.5.17 当前审计结论。
