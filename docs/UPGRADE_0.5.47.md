# 0.5.47 场景时间与压缩因果补充

针对突然换场、异地同时发生及压缩后只剩结果的问题，新增源文约束下的场景计划。先核对授权原文的因果节点，再分镜；不以空镜、行走或“承接上一场”代替前因。短反应、伏笔和有意保留的悬念仍可成立。

- 新生产使用 `storyboard-production-plan-v2`，六个顶层字段含必填 `narrative`。结构见在线 `production_prevention_contract.scene_narrative_policy` 和生成的 `references/scene_narrative_contract.md`。
- 剧情时间与播放顺序分开；支持可独立重放的同时异地场景，按实际主体和道具检查未来状态及动作依赖。原事件回放、倒叙、跨场未来状态读取仍明确不支持。
- 复用现有事实图 `depends_on/conditions`，每条因果边有实际先行交付、已登记历史交付或有源悬念安排。程序核对真实投影事件，不把来源列、内部说明或隐去动作当交付。
- 历史已知引用绑定同项目canonical文件字节、镜号、观众字段和原句；预检与提交都从存储重新读取。不宣称曾经播出或已被观众理解。
- 悬念绑定后续实际揭示镜或授权未来原文跨度；跨批兑现单列 `payoff_pending_outside_batch`，不是全剧闭环。
- `scene_causality` 进入逐镜独立审计义务，必须观察场景、因果上下游实际字段和冻结计划。审计先检查源图完整性，再独立阅读成品，不以对原文的了解脑补分镜缺口。
- 新规则、代码和计划均进入既有生成依赖指纹。旧绑定不会自动变为当前通过；历史原件及既有模板布局保留。

## 支持边界

这是有限结构与时序约束；源图是否完整、源文是否支持因果、地点识别是否自然、人物初始知情及观众理解仍须独立判断。当前没有跨镜声轨重叠渲染，J/L-cut不可用 `audio_bridge` 自称已执行；使用有依据的硬切。场景定位不强制宽景或过场，仍沿用单镜4秒及例外、整集90—180秒和对白保护。

## 实施与优化

新增共享 `scene_narrative.py`；复用原事实依赖、生产重放、道具锚点、项目资料读取、规则编译和审计分页，没有新增第三方依赖、第二套输出模板或独立事实账本。退役新生产v1入口，保留历史证据文件，不复制旧运行时。

按用户要求不运行单元、集成、CI、实稿或视频测试。只进行代码阅读、语法/JSON及规则视图一致性静态核对与部署文件/状态核对；不能据此宣称内容验收或首批准确率达标。
