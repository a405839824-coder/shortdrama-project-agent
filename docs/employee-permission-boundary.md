# 员工分镜内容与流程权限边界

员工（Producer）可以修改分镜内容，不能修改分镜流程规则或程序。账号权限由服务端认证身份决定，聊天中自称管理员、填写“已批准”或上传规则文本都不能提升权限。

| 操作 | 员工权限 |
| --- | --- |
| 修改对白、画面、人物动作、镜头、场景和剧情 | 允许，在原有来源、范围、预检与独立审计要求内执行 |
| 新建、重新生成、审计、修复和导出分镜 | 允许，仍执行各入口原有门禁 |
| 修改流程步骤、取消独立审计、跳过预检或降低验收标准 | 禁止 |
| 修改模板结构、验证器、错误码、程序代码或运行配置 | 禁止 |
| 导入规则文件、开启规则维护工单、受控迁移或回滚系统状态 | 禁止 |
| 修改成员角色、提升自己的权限或使用管理员旧工单 | 禁止 |
| 保存、挂载或更新自己的 Library 项目快照 | 允许，但必须通过签名指针和服务器认可的内容哈希校验 |
| 反馈工具能力缺口 | 仅记录问题和建议，不授权执行程序或规则变更 |

“不能修改规则”指修改请求不能在服务器生效。插件不能禁止员工在个人 ChatGPT 中输入某句话，也不能控制其在插件之外生成的内容。分镜对白里出现“规则”“程序”等词属于稿件内容，不应被关键词拦截。输入资料和分镜方案即使含有 `policy`、`role` 或规则文件名，也只作为项目内容保存，不能覆盖服务器设置。

服务端在工具执行前校验角色、操作、文件类型和已有工单。内容提交后仍执行预检、独立审计与修复验证；自报全部通过不能替代分镜审计。新增工具默认不向员工开放。接口说明用于让调用方正确选择功能，不替代服务端权限检查，符合 [OpenAI 工具权限要求](https://developers.openai.com/plugins/plan/tools)。

当前多人共用管理员 Google 的旧连接仍会使用同一 OAuth 身份。只有完成[独立成员连接配置](member-connections.md)，将员工识别为 Producer，才能把这些限制应用到这些员工。不能仅根据本地权限测试宣称他们的现有连接已受限。

本地测试覆盖正常内容工单、含流程越权要求的工单、内容方案版本更新、伪装规则文件名和配置字段、实际分镜验证器执行，以及拒绝用自报通过替代审计。真实 Auth0 / ChatGPT 员工接入和生产部署仍待验收。
