# 0.5.64 — 审计分类、误触发修正与生产前检查

本次实现已授权的第一批、第二批改进。保留现有十一列表格、27 字段、
原文对白保护、权限隔离、来源及连续性门禁、八层独立审计和签核要求。
管理员互相只读查看的范围不变；升级不会修订历史分镜或改写旧结论。

## 第一批：有界格式处理与准确计数

- 新的未绑定输入可在记录原始候选后，运行
  `bounded_normalization.normalize_project_literals`。只处理明确等义的配乐
  禁止表达、整值无对白写法和能绑定实际发言的重音引号。
  输出仍使用 `禁止额外配乐` 和固定音色结构。结构化生产请求仅规范化有源
  重音标点，动作、原文和来源图保持不变。记录每个修改的位置及前后值。
- 条件例外、双重否定、肯定配乐、矛盾表达和不能确定归属的重音不自动改写。
  已绑定候选发生变化需要重新建立依赖；不能用旧证明重新签名。只读审计和
  历史文件不运行写回规范化。
- 静态检查区分已支持的否定约束与肯定动作。“不定格于半眨眼状态”不再仅因
  包含眨眼字样报成动作；同句中另有真实眨眼过程仍须报错。
- 肩线等局部归属明确人物，不当作额外人物要求表演；缺拥有者时继续报告
  输入映射未知。正文已写明分先后经过、有效的近远声层时按实际内容识别，
  空标签、否定声源和未支持的开放语义不因此获得通过。
- `query_project_issues.data.evidence_metrics` 分开五类：已复核内容、内容风险
  候选、格式规范、资料待补、疑似误报。只读诊断附 `issue_classification`。
  独立确认需要逐项证据，机器报警不会自动升级为确认内容错误。
- 同时返回历史观察条数、同文件版本问题数、重复观察数和文件版本资料缺口数。
  每项比例含分子、分母及定义；问题保留事件引用，缺文件指纹不按同名文件
  跨事件归并。分类和聚合不删台账、不改变原始门禁或签名结论。

## 第二批：真实输入绑定、排时与修复联动

- `production_binding` 为新候选核对 ProjectStore 中实际来源字节与指纹，并
  绑定当前运行、规则、Schema 和验证器。仅在完全缺失时补服务端当前项目
  版本/工作流信息；显式冲突、旧值、空值不能被覆盖。来源锁、审计覆盖和
  防错证据不补造。缺证按稳定范围返回待补信息。
- `draft_observations/OBS-*.json` 保存原始候选快照、准备后哈希、准备修改和
  生产绑定。结构化请求继续保留 `request.original.json` 和
  `source_graph.original.json`。服务端只能证明收到的第一个候选，不能证明
  聊天中没有更早稿或内部修订；历史缺失首稿不回填。
- `timing.metrics.planning_summary` 和生产预检的 `timing_diagnostics` 区分
  显式计划重叠、估算重叠、文本容量不足、其他结构错误及慢速提醒；片段绑定
  来源镜头和文本哈希。没有实音轨时 `actual_audio_verified=false`，
  `actual_audio_measurement_status=not_provided`，渲染也仍未实测。
  字速参数和现有排时门禁不放宽，不删对白、不加速或突破镜长取得通过。
- `quality.repair_diff.dependency_plan` 根据真实前后差异提示联动复核：
  对白涉及声法、口型、听者、原文知情与时长；站位涉及机位、初态、关键帧
  和前后镜；时长涉及后续时间轴及跨镜音轨。计划不是审计结果，始终要求
  完整当前候选机器回归与八层独立复审。

## 统计边界与验收

问题构成比例不是生图或视频失败率。误报率、修复复发率、真实首稿内容错误率
在缺少相应复核样本时返回未知及原因，不能填 0；可计的已复核问题镜头比例
也需要完整独立覆盖和逐项证据。首次送审不等于真实首稿；本轮新发现不自动
归因于修复引入。软件回归通过不证明首稿达到 98%，也不证明生成质量已提高。

规则仍以 `references/rule_registry.json` 为唯一可编辑当前来源；修改后用
`scripts/rule_registry.py --write` 编译，并执行只读 `--check`。
本次不修改 `historical_rule_baseline.json`，不改变旧原子规则和错误语义来
规避检查。当前输入解释和报告策略补入原有工作流说明，不另建模板。

发布前必须完成定向正反例、既有回归、规则及技能校验。上线后核对实际
0.5.64 版本、当前规则指纹、全测试证书和管理员读取范围。真实生成改善需
另用固定原文与配置、完整保留首稿和独立评价的样本进行测量；本升级不为
第 36—80 集签发新的内容通过结论。

部署保存与恢复采用本版本专用、签名且一次性的转移记录，先核对备份和
恢复字节，再恢复请求。操作步骤见 `deploy-audit-generation-0564.md`。
