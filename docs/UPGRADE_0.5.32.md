# 0.5.32：字段归属与 R5 输出

机位中曾能混入人物动作或声音，音色子项只核对格式；旧标点检查还要求在画面正文重复发声指导。这会使同一要求在不同字段间反复搬动。0.5.32 将字段内容合同接入生成编译、预检、修正和输出，标点执行改为读取音色，正文保留可见动作与准确对白。

规则以 `skills/shortdrama-storyboard/references/rule_registry.json` 为唯一来源，生成 [27 字段、音色子项和 GPT 段落合同](../skills/shortdrama-storyboard/references/field_content_contract.md)。插件启动说明和认证状态返回当前合同；Admin 与 Producer 执行同一内容检查，Producer 无规则修改权。

- 原有 27 字段、十列顺序保持；母版 E、GPT F、逐镜阅读页从同一份数据生成，模型不提交另一份 E/F 正文。
- 机位中的演员动作、声线和发声参数，以及音色子项中已支持的错列模式，在生成记录/预检/输出处拒绝。错误带字段路径、角色和原片段，不静默删句或搬列。
- 基础声线、言语行为、当前表达、发声方式分组、六个发声子项和禁止语气分别受限。数字制作时间码继续只保存在内部正文绑定中。
- 当前真实对白、来源原句、当前可见道具文字及声画事件关联不因出现同一个词而一律删除。引号本身不构成豁免。
- GPT 使用十个固定段落和一个可选文字造型锚。声音、运镜、环境过程和图片绑定状态不作为静帧正文。造型文本在参考字段中以独立的 `文字造型锚：` 行标明，素材/绑定状态另起标签行；未标记的旧参考信息保留在 G 列，不猜测成造型。
- 输出包含每集的 `逐镜阅读`、`正式分镜母版`、`使用与来源`，保留原 `00_范围与审计` 及隐藏 canonical。读取序列化文件，核对所有可见阅读页、母版与来源页的值，再核对 canonical 和审计页；改动阅读页也会使核验失败。
- 可见投影版本升级为 `shortdrama-projector/0.5.32`。已有 0.5.31 输出的 `shortdrama-projector/0.5.5` 使用逐字冻结的旧投影器回读。修改版本标记不能绕过实际值和摘要核对；旧文件可读不代表通过新规则。

生成流程继续使用 `production-authoring-request-v1`：来源图与原始决定先留档，摄影视场、初始状态、光源和事件依赖由现有结构化编译器推导，返回唯一 canonical。兼容的手填 canonical 仍存在并执行同一字段检查，其来源在预检返回值中明确标为 `canonical_compatibility`，不能声称已执行结构化生成。未提交的模型内部改稿不在服务器可观察范围。

字段规则有明确边界：结构与已支持角色检查可以阻止相应的错误，但不是任意自然语言的完整语义证明。来源理解、动作选择、复杂遮挡、对白自然语速和修正引入的新因果错误仍须单独验证。本次不启动新的真实分镜生产/审计循环，也不以软件测试宣称真实首稿使用率达到 98%。

本次保持现有工具型 MCP 架构、公共工具名称/参数和认证方式；服务器执行内容检查，工具说明向模型公开当前限制。工具合同设计参照 [OpenAI 工具规划](https://developers.openai.com/plugins/plan/tools) 与 [MCP 服务文档](https://developers.openai.com/plugins/build/mcp-server)。

验收应覆盖正反例、生成失败留档、两条预检输入、实际 XLSX 回读、历史文件、权限、HTTP/stdio、打包及完整 CI。部署后核对当前版本和真实运行代码的相同测试，并比对配置、密钥指纹、角色记录和 Library 指针。软件通过、部署完成与内容独立审计保持分开。
