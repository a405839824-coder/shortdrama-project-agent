# 0.5.54：握手、松手及生成校验一致性

原文“老夫人握住苏清柳的手”需要手与手之间实际接触。此前 `contact_actor/grasp` 只接受腕部，不能用握腕或扶手代替原动作。

用户明确授权补齐握手和松手。本次扩展现有握持与释放链，限定真实可达、开放且空闲的手，保持接触期间的占用及状态约束，释放必须对应实际握持。原有腕部能力、室外日光、失败推抵、基础声线和正式模板保持。

软件回归、真实镜头构造、独立内容审查和正式交付分别核验，软件通过不等于分镜已交付。上线仍使用既有单次签名启动恢复，只更新到本次版本绑定，保护当时全部临时项目与导出文件；不修改历史快照、密钥或Library指针。

追加授权修正生成文本与其事件校验的一致性。具体眉眼唇角动作使用相同事件名称，保留原画面文字及严格事件匹配；按真实几何轨迹登记镜内可见人物，并在原字段内区分首帧可见部位，两个GPT关键帧投影仅取真实首帧子集。时长分析复用现有实名、有界、非否定的眼部可见区间识别，避免将合法区间误判为额外动作阶段。未增加模板字段或放宽未知人物、未出现动作、错误时间和伪造绑定的拒绝条件。

完整候选另暴露三个同类问题：折叠空阶段的末尾换行在compact投影被去除，破坏原计时哈希；手部镜头的“眼睛不入画”被误当成面部表演；生成器的“画面正前侧”方向未被光影门禁识别。本版保留已验证的精确计时原串，按实际实名可见部位检查表演，补齐同一方向词。画外注视仍更新世界状态但不生成可见眼球动作，有源注视不可见时仍拒绝并要求修正机位。未知场景仍报错，不能从地点名称或纸窗猜测空间类型。

本版不修改知情规则。候选计划把本人未来动作结果登记为开场已知的问题已单列，不能以软件通过或备注解释为正式语义通过。
