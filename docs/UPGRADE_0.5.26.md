# 0.5.26：审计后的本批修正模式建议

此前审计报告没有固定说明本批修正适合哪种思考模式，用户需要逐次追问。本版在首审、复审、修复后独审及缓存报告返回中增加 `repair_mode_recommendation`，技能交付时将它呈现为“本批修正模式建议”。本地或历史报告缺少此字段时，按同一政策补写附注。

唯一规则源为 `references/rule_registry.json` 的 `runtime.audit_repair_mode_advice`。轻量适用于有明确位置和修复动作的机械修改；中等用于局部语义修正；超高用于跨镜依赖、源文覆盖或结构联动；最高用于冲突裁决和反复修复的根因定位。按问题组分别列出依据、镜号或原报告位置、可用替代档位和升级条件，不以错误数量单独决定档位。整批建议取最复杂问题组，简单的独立问题仍可用较低档位。

这是一项可配置的经验建议，未做模式准确率对比实测。模型与实际可选档位由当前界面或用户提供；未知时保持未核实，不绑定特定模型名称、不声称自动切换，用户可用其他模式。审计通过且无待修内容问题时写“无需修正”；审计阻塞或问题信息不足时写“待补充建议”，不得凭空认定无需修正。

建议作为审计结果的附注返回，不写入已签名的原报告、证书、工作簿或历史台账，不改变结论、门禁、修复授权和审计轮次。建议模块失败时只要求补充报告，原审计结果仍返回。缓存重放重新附加当前政策建议，原证据和轮次不变。用户已授权修复时直接继续，不为模式选择追加确认、换窗或角色分配。

验收覆盖：简单大量问题不会仅因数量升级；跨镜和冲突问题分级；混合问题分组；无问题、非阻塞提示、缺失清单与阻塞区分；模型映射可修改；建议故障不改审计结果；真实首审、修复后终审、缓存及复审返回。既有完整回归仍为发布条件。
