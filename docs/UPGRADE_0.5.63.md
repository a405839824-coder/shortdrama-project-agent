# 0.5.63 — executable rule bindings and current boundary evidence

This release closes reproduced rule-checking and audit-routing gaps.

- Validator registrations name existing Python entry points. The registry check
  rejects missing files, out-of-scope paths and nonexistent handlers. Shared
  inline checks remain in `validate_project`; no empty wrapper functions were
  introduced.
- The existing reviewed conflict decisions, exceptions and global priority order
  are preserved in the historical baseline. An unreviewed contradictory edit
  cannot become valid just by regenerating all views. This is change control,
  not a general natural-language satisfiability solver.
- The packaged skill entry declares the actual registry revision. Runtime and
  rule views continue to come from the sole editable registry.
- State and sound audit obligations include both neighboring actual cut,
  starting-state, picture and sound fields. Their hashes and mandatory observed
  references change together, including in compact paginated reads.
- A bounded current-speech/silence contradiction is visible to the ordinary
  validator and cannot be overridden by a reviewer PASS. Explicit terminal
  events can be read from the actual cut field; unknown continuity stays unknown.
- The explicit review serializer accepts only decisions keyed to individual
  current obligations. It rejects rule defaults, missing decisions and stale
  dependency bindings, and never creates a PASS.
- Window-neutral repairs may share an authenticated transport session while
  retaining distinct work orders and server-issued execution identities.
  Legacy session separation and identity-reuse rejection remain enforced.

The output template, protected dialogue, voice definitions, timing profiles,
source files, permissions and historical artifacts are preserved. Existing
certificates do not become current certificates by changing their version.

Validation includes the previously missed EP55 boundary, contradictory registry
mutations and legal silence/stillness/offscreen/recollection near-misses.
The historical per-episode default-PASS serializer is retained only as evidence;
it is not the current serialization route. A declaration can still be wrong:
bound quotations and software checks do not prove open-ended semantic truth.

Deployment uses a fresh signed single-use `.upgrade-rule-execution-0563`
transfer. It must preserve the current runtime project/export bytes and protected
state before the new process begins accepting requests. Existing consumed
transfer markers are not reused.
The current complete tree exceeds 5 GB; this transfer has its own 8 GiB expanded
ceiling, with the unchanged 2 GiB compressed ceiling. Older transfer limits stay
unchanged. Preserve the administrator mutual-read feature and its verified
dispatch-drain/retention-lock maintenance procedure from the current main branch.

Software, deployment and real-manuscript acceptance remain separate. No full
36–80 content PASS or user archive signoff is issued by this upgrade.
