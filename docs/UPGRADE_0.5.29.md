# 0.5.29：合并生产约束与账号权限

0.5.29 将原本独立开发的 0.5.27 首稿质量、生产防错和剧情约束合入线上 0.5.28 的 Admin / Producer 版本。它保留已有账号、命名空间、OAuth、Library 存储与历史证据规则；新版本号本身不证明部署完成或真实首稿达到 98%。

## 发布内容

- 分镜生成前绑定授权源文、对白出现位置、动作与道具状态，使用同一声明派生实际正文与执行字段；静帧文字、环境和表演约束参与生产预检。
- 首次候选、失败尝试与修订分别保存，内容正确率和直接可用率分开统计；当前总体与每集的目标均为至少 98%，硬错、重大问题和已知问题复发要求为零。没有原始首稿与完整独审证据时，指标保持未知。
- 剧情正文前提交原文、授权、事实、场景状态和依赖计划。计划与正文各自复核，修改后的相关旧结论失效；不确定的上游事实阻断受影响内容，受影响范围无法定位时不能把整稿判为通过。
- 正文、首稿、失败尝试和审查记录按精确内容及签名留档。修订核对最近适用候选和影响链，保留以前的失败记录；历史通过不能冒充当前版本通过。
- 继续在服务端实施 Admin / Producer 权限；Producer 允许已有生产、审计、修正、导出和新增剧情操作，未知工具与维护操作仍默认拒绝。人工最终签核保留 Admin 权限。

## 工具目录

Admin 共 24 个工具，Producer 共 21 个工具。新增：

| 工具 | 用途 |
| --- | --- |
| `preflight_narrative_plan` | 绑定精确源文及授权，验证正文前的事实与场景计划 |
| `review_narrative_artifact` | 记录绑定当前计划或正文的独立审查 |
| `record_narrative_attempt` | 保存原始候选和失败尝试，不用修订覆盖首稿 |
| `read_narrative_record` | 读取不可变记录；`record_id=contract` 返回当前剧情契约 |

Admin 目录继续包含 `manage_user_access`、`recover_storyboard_handoff`、`signoff_task`；Producer 不可见且不可调用这三项。服务器角色隔离不能证明两个实际语言模型或两个模型上下文彼此独立。

## 部署与核实

本文件描述发布内容和验收要求，实际部署结果以单独保存的发布记录为准。使用基于 0.5.28 合并的发布树，保留原 Railway 服务、单副本、域名、卷、OAuth 配置及账号角色。不要直接上传未合并的 0.5.27 开发树。

部署后应核实 `/health` 返回 `version=0.5.29`、`account_access_contract=admin-producer-v1`，未认证 MCP 请求仍被拒绝，认证后的 Admin / Producer 工具数分别为 24 / 21，并实际调用新增只读契约入口。客户端发现目录后，新增工具才能用于新的生产任务；旧稿件和历史审计不会被版本升级自动改写。

## 验证口径与已知边界

- 合并后的软件回归、权限验证、HTTP / stdio 冒烟与打包检查须针对同一发布树完成，不能直接借用旧分支的通过数作为当前发布证明。
- 规则可以阻断已结构化表达且可检验的错误；自然语言是否忠于原作仍需要完整独立内容审查。模型没有提交到服务端的内部思考或未记录草稿不可由插件观测。
- 当前剧情计划按故事发生顺序表达；倒叙和多时间线不能仅凭显示顺序假定已经被完整验证，需要明确建模和相应审查。
- 本次软件合并不声明真实首批使用率已达到 98%，也不声明固定一到两次审计能发现或消除全部问题。软件通过、线上生效、真实稿件验收分别记录；生产约束不以任意禁止继续修正替代质量控制。
