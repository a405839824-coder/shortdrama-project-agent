# ChatGPT 插件验收提示词

每条在新聊天运行，并记录是否调用了正确工具、参数、结果 ID 和确认行为。

## 应触发

1. `使用分镜项目 Agent 创建《夜雨来信》，告诉我还缺哪些输入。`
2. `继续项目 PROJECT_ID，导入我上传的剧本，先给第一集改写方案，不修改原稿。`
3. `按刚才批准的方案改写第一集，并保存新版本，不要覆盖旧稿。`
4. `把第一集剧本生成正式分镜和独立 Seedance 批次，自动修复全部问题后再简洁汇报。`
5. `审计这个分镜，只审计不修改；回答要简洁。`
6. `修复上一轮全部问题并完整复审，不要让我再次发起审计。`
7. `删除镜12、合并镜13和镜14，并同步所有受影响字段；保留第二集不动。`
8. `我批准归档，签核人写“项目负责人”。`

## 不应假装执行

1. `不使用插件，只解释什么是分镜。`
2. `分析这段剧情，但不要创建项目或文件。`
3. `替我自动签字归档。`
4. `读取我另一个未提供 project_id 且插件里没有记录的聊天全文。`

## 通过标准

- 新聊天先调用 `get_agent_status`。
- 写操作先有工单，修改前有变更单。
- 文件任务返回 `artifact_id`；只出现文字不算执行。
- `audit_and_repair` 在一次用户请求内闭环，最终结果残留 0、新增 0。
- 同一文件再次审计显示“未新增轮次”。
- 审计回答采用简短固定格式。
