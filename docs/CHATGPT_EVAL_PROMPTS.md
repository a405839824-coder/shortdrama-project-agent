# ChatGPT 插件验收提示词

每条在新聊天运行，并记录是否调用了正确工具、参数、结果 ID 和确认行为。

## 应触发

1. `使用分镜项目 Agent 创建《夜雨来信》，告诉我还缺哪些输入。`
2. `继续项目 PROJECT_ID，导入我上传的剧本，先给第一集改写方案，不修改原稿。`
3. `按刚才批准的方案改写第一集，并保存新版本，不要覆盖旧稿。`
4. `完整读取我上传的小说第一章，先建立剧情地图、取舍台账、人物认知和对白保护，再生成正式分镜；禁止逐段直接转镜头。`
5. `在生产窗口把第一集剧本生成正式分镜和Seedance 2.5独立执行批次，完成生产预检并交给独立审计；不要冒充审计通过。`
6. `在新的独立审计窗口读取生产交接包，只审计不修改；回答要简洁。`
7. `上一轮独立审计失败。我明确授权在第三个独立修复窗口消费签名修复包并修复全部问题；完成后交回原审计窗口，不要在修复窗口签发最终通过。`
8. `删除镜12、合并镜13和镜14，并同步所有受影响字段；保留第二集不动。`
9. `我批准归档，签核人写“项目负责人”。`
10. `生成古代闹市全景：必须写普通人物密度、地点角色、错峰动作、近中远环境音和Seedance声画复现；修正后保存。`
11. `审计这个公共街道分镜，其中环境音只写“街道嘈杂声”，不要放过这个问题。`
12. `继续这个项目。原文和规则没有变化，请用批量范围读取，不要重复逐页读取；先告诉我生产handoff是否匹配，再独立审计。`
13. `我明确授权在独立修复窗口，只修复独立审计证书确认的镜S001“光源来源”，其他字段不动；保存新版本，完成全表生产校验后交回原审计窗口复核。`
14. `不做独立审计，直接把刚生成的分镜签核归档。`

## 不应假装执行

1. `不使用插件，只解释什么是分镜。`
2. `分析这段剧情，但不要创建项目或文件。`
3. `替我自动签字归档。`
4. `读取我另一个未提供 project_id 且插件里没有记录的聊天全文。`

## 通过标准

- 新聊天先调用 `get_agent_status`。
- 写操作先有工单，修改前有变更单。
- 文件任务返回 `artifact_id`；只出现文字不算执行。
- 小说章节生成前必须完成`source_ingestion`证据，核心事件、因果、人物变化、保护对白和源文处理覆盖率均为100%。
- 正式10列母版执行字段必须是`Seedance 2.5独立正式执行分镜`。
- 公共场景必须写密度、地点角色、错峰动作、空间层次、具体近中远声源和对白避让；只写“人群/环境声”必须阻断。
- 正式分镜与Seedance批次必须使用同一套普通人物与声源事实；无因空场、匿名群演完整台词和时代错位声源必须阻断。
- `audit_and_repair` 可属于同一工作流链，但每个角色必须使用自己的工单：生产工单交给原始 `audit_only` 工单；只有审计失败并获显式授权后才新增独立 repair 工单，修复结果必须回到原 `audit_only` 工单复核。审计通过时不创建第三窗口；不得把审计和修复合并为同一权限、窗口、会话或工单。最终结果残留 0、新增 0。
- 生产提交只显示“生产预检通过｜待独立审计”；首次独立审计必须重新判断，只有同一安全缓存键的再次独立审计才显示“未新增轮次”。
- 长章节优先使用`bulk_ranges`，相同ETag使用`if_none_match`，不得因提速漏读正文。
- 局部修复必须调用`commit_storyboard_patch`并绑定基础canonical哈希、独立审计证书、问题码和影响范围；结构/边界/认知/原文/编号/时长变化必须拒绝patch，并改走绑定同一签名修复包的完整场景/分集重建。
- 分镜没有精确版本的独立审计通过证书时，`signoff_task`必须阻断归档。
- 审计回答采用简短固定格式。
