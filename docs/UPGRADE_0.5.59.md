# 0.5.59：欠证状态与完整报告读取

修复两个实际流程问题，规则适用于所有项目。

1. 审计无法测量首稿质量时，原写入器及 JSON schema 允许 `unavailable`，手写状态校验却只允许 B/C，造成插件自己写出的状态被判非法。统一状态合同；新增记录将证据不足与实际低质量分开，历史记录兼容读取且不重写。
2. 工作表首行仅为合并标题时，原预览按首行非空表头截列，后续行的报告值和问题详情被漏掉。读取保留实际有内容的列，空表头使用确定性名称，既有正式母版字段映射不变。

## 保持的边界

- `unavailable` 不转换为 B/C、不虚构百分比，也不清除现有质量限制。
- 完整审计和补证可继续，生产门禁及真实独立 PASS 的解除条件保持。
- 不修改任何真实分镜正文、母版、关键帧、阅读页、音色、原台词或时长规则。
- 不修改成员身份、角色、配置或密钥；管理员与员工共用的服务端修复不代表员工客户端已完成实际验收。
- 软件回归及部署核验不等于真实分镜审计通过。欠证仍须在真实报告里显示 UNKNOWN/无法测量。
- 使用 `.upgrade-0559` 的新签名迁移清单保存运行中项目和导出文件，不重放旧清单。

真实内容审计、证书、派生工作簿回读均通过线上插件完成；软件测试仅使用合成夹具。
