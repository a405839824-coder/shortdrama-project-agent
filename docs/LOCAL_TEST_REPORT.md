## 0.5.0必须验证的契约

- 新写入的canonical每镜只接受27个模型语义字段；独立`人物调度、动作与表演、台词、发声方式、标点语气、心理音轨属性、生成批次`必须被拒绝。
- `空间站位描述、起始状态、音色、光影、光源来源、光源方向、色温倾向`保持独立并接受缺失与连续性校验。
- `画面内容`可以包含动作、表演、精确对白和最多3段可选连续时间；时间段必须从0开始、无缺口、无重叠并闭合到本镜时长。
- 正式Excel严格为10列：`分镜序号｜时长｜累计时长｜功能类型/场景连续性ID｜正式分镜母版·字段合并｜GPT关键帧生成指令｜参考图锚定｜覆盖原文｜原文依据类型｜原文支撑句`。
- `正式分镜母版·字段合并`是唯一完整视频执行真值；`GPT关键帧生成指令`为导出时确定性生成的单帧可视投影，并删除时间、对白、口型和声音信息。
- canonical与新导出不得出现独立Seedance列、独立执行提示词、`batches`对象、镜内`生成批次`或“生成批次”工作表。
- 一次导出只执行一次canonical紧凑归一、一次正式母版投影和一次GPT投影；生产、delta、审计、修复与后台任务均不得生成Seedance批次或第二套视频叙事。
- 0.3.x/0.4.x历史artifact保持只读；Legacy迁移只创建新的R10.1 successor，语义折叠一次且不回写旧字段。无法可靠得到必需事实时必须阻断。
- 生产、独立审计和条件修复的权限、handoff、证书、防重放、CAS、保护范围和返回原审计窗口规则继续通过完整回归。

## 上传样本实测

测试输入为用户上传的`样本.xlsx`，只读解析，未改写原文件。

| 检查项 | 实测结果 |
| --- | --- |
| Excel列 | 与约定10列名称和顺序完全一致 |
| 新导出可见工作表 | `00_范围与审计`、`正式生产母版` |
| canonical镜头语义字段 | 27个模型字段；样本无服务身份字段，生产提交时服务可另加`shot_uid、episode_id、scene_uid` |
| 独立批次 | 无`batches`、无Seedance列、无生成批次页 |
| 退休标签 | `运镜主体、运镜功能、叙事功能、人物调度、动作与表演、台词、发声方式、标点语气、心理音轨属性、生成批次`在正式母版中均为0次 |
| 光照 | `光影、光源来源、光源方向、色温倾向`各输出1次 |
| GPT关键帧 | 对白、口型、发声、声音、配乐和时间码残留均为0；人物/场景参考图锚点保留 |
| 单镜原始行字符 | 1,362字符 |
| 紧凑canonical模型字段值 | 849字符，比样本原始行少37.67% |

37.67%只表示这一个样本镜头的模型语义载荷缩减，不等于端到端时间缩短37.67%，也不能直接外推59镜。正式母版和GPT列仍会在Excel中出现，但它们由服务端确定性投影，不再要求模型重复撰写或保存。

## 性能结论边界

0.5.0从架构上删除了模型重复编写的独立Seedance长字段、生成批次、批次包装和后台预生成，并把正式母版与GPT关键帧改成导出投影。追踪契约要求`legacy_generation_calls=0`、`seedance_batches_generated=0`和`model_authored_derived_chars=0`，delta还用调用次数测试保证合并后完整canonical只物化一次。

局部修改的确定性工作量缩减可以按镜头数计算：59镜中只改5镜时，模型只生成8.47%的镜头，生成镜头数减少91.53%；改10镜时只生成16.95%，减少83.05%。这仍是“生成范围”缩减，不等于同百分比的墙钟缩减，因为服务端全表校验和独立审计继续保留。

具体时长和压缩率必须使用相同源文件、相同镜头范围、相同模型/服务档位、相同缓存状态和相同最终输出契约进行0.4.x/0.5.0 A/B回放，并同时记录模型实际输出字符、端到端墙钟、canonical/XLSX字节、production/audit两条追踪以及最终质量问题数。在该A/B完成前，不发布分钟数或百分比结论。

当前本地插件源码、测试和技能包已通过；云端Railway/Auth0端点未在本次本地回归中重新部署或验收，因此不得把已连接的0.3.0云端实例宣称为0.5.0。
