## 0.5.3必须验证的契约

- 新写入的canonical每镜只接受27个模型语义字段；独立`人物调度、动作与表演、台词、发声方式、标点语气、心理音轨属性、生成批次`必须被拒绝。
- `空间站位描述、起始状态、音色、光影、光源来源、光源方向、色温倾向`保持独立并接受缺失与连续性校验。
- `画面内容`包含动作、表演、精确对白、六维发声、听者反应和恰好3段连续Seedance 2.5时间；时间段必须从0开始、无缺口、无重叠并闭合到本镜时长。
- 正式Excel严格为10列：`分镜序号｜时长｜累计时长｜功能类型/场景连续性ID｜正式分镜母版｜GPT关键帧生成指令｜参考图锚定｜覆盖原文｜原文依据类型｜原文支撑句`。
- `正式分镜母版`是唯一完整视频执行真值；`GPT关键帧生成指令`为导出时确定性生成的单帧可视投影，并删除时间、对白、口型和声音信息。
- canonical与新导出不得出现独立Seedance列、独立执行提示词、`batches`对象、镜内`生成批次`或“生成批次”工作表。
- 一次导出只执行一次canonical紧凑归一、一次正式母版投影和一次GPT投影；生产、delta、审计、修复与后台任务均不得生成Seedance批次或第二套视频叙事。
- 0.3.x/0.4.x历史artifact保持只读；Legacy迁移只创建新的R10.1 successor，语义折叠一次且不回写旧字段。无法可靠得到必需事实时必须阻断。
- 生产、独立审计和条件修复的权限、handoff、证书、防重放、CAS、保护范围和返回原审计窗口规则继续通过完整回归。
- `mark_performance_stage`只在显式性能排障中记录五个服务器收件检查点；普通生产不增加标记调用。诊断记录只接受ID、枚举和计数，绑定项目/工单/角色/会话，区分`tool_bracketed_chat`与插件`server_only`，且保持所有逐镜质量字段不变。

37.67%只表示这一个样本镜头的模型语义载荷缩减，不等于端到端时间缩短37.67%，也不能直接外推59镜。正式母版和GPT列仍会在Excel中出现，但它们由服务端确定性投影，不再要求模型重复撰写或保存。

## 性能结论边界

0.5.0紧凑母版继续负责删除模型重复编写的独立Seedance长字段、生成批次、批次包装和后台预生成，并把正式母版与GPT关键帧改成导出投影。0.5.3在其上增加无API诊断层，不改变canonical或Excel合同。追踪契约仍要求`legacy_generation_calls=0`、`seedance_batches_generated=0`和`model_authored_derived_chars=0`，delta仍保证合并后完整canonical只物化一次。

局部修改的确定性工作量缩减可以按镜头数计算：59镜中只改5镜时，模型只生成8.47%的镜头，生成镜头数减少91.53%；改10镜时只生成16.95%，减少83.05%。这仍是“生成范围”缩减，不等于同百分比的墙钟缩减，因为服务端全表校验和独立审计继续保留。

0.5.3可在没有API时记录`task_started → inputs_ready → plan_ready → canonical_ready → delivery_ready`的服务器收件间隔，并汇总本轮真实插件trace。它可定位最大观察区间，但仍不能精确拆分模型排队、隐藏思考、令牌速率、客户端传输和最终渲染。思考模式影响必须在相同源文件、镜头范围、route、窗口类型、缓存状态和输出合同下做至少一组受控对照；单次运行不作因果结论。

当前本地插件源码、168项测试、清单和技能包已通过；云端Railway/Auth0端点尚未部署本提交，因此在云端健康检查和15工具发现完成前，不得宣称已连接实例为0.5.3。
