# 0.5.45 审计完整性与误报修正

本版处理五份审计记录和线上流程核查暴露的执行问题：缺少部分镜头语义证据仍可签发PASS、把道具当人物要求表演、失败缺少可定位记录，以及未提交的项目状态容易被误读为已完成。

## 当前执行变化

- 审计清单由服务器根据当前canonical、来源、规则和运行程序生成。每镜13类必查义务；字段归属观察覆盖全部27字段，另保留既有来源、相邻对和逐声道证据。缺项、重复、未知、旧指纹和错误字段引用均不能取得当前证书。修复不只复验问题镜，也重新检查整批及横向模式。
- 通过公开只读 `read_project_artifact(section="audit_obligations")` 分页取得清单。旧客户端用该响应描述的 `audit-coverage-v1:` 逐层分片封套，经过同一验证。服务器不代替审计员填写判断。旧签名记录保持不变，缺当前完整覆盖的历史证书不能用于当前正式交付、签核和批次续作。
- 大批次在现有 `audit_storyboard` 内按 `semantic-obligation-pages-v1` 分页暂存实际判断，再显式提交全部页ID做最终封合；旧客户端使用独立的 `audit-coverage-page-v1:` 封套。暂存页绑定当前产物、工单、交接、审计身份和规则，`coverage_pending` 不签发通过，也不允许交付。这样不要求模型在一次工具调用中生成整批几千项判断。
- 人物、道具与未知对象分别处理。纯道具镜不要求眼神；自然静止不强制换焦、眨眼或听者反应。实际可见性、目标、闭眼和眨眼时序冲突继续拦截。类型不明报告输入映射问题，不凭未知名称补造人物。
- `diagnose=true` 支持沿用公开工具的section/offset/limit/max_chars分页；大问题可分块读取完整详情。输入映射、证据依赖、候选内容告警分别统计，响应明确不是独立审计证书。
- 状态区分未正式提交、待审和需要核验回执；零已登记问题不代表内容正确。正式完成始终核验精确产物的当前回执和文件哈希。
- 日志为失败保留安全错误码、可观察阶段、调用关联号及版本指纹；不保存异常正文、台词、访问令牌或签名。旧库幂等迁移，旧空原因保持未知；业务FAIL与工具调度成功分开。
- 移除与现行规则冲突的固定修复轮数硬上限；显式用户停止、额度和宿主执行预算仍有效。

## 结构与边界

覆盖验证、可见对象识别、诊断分页、状态摘要及日志诊断分别提取为独立模块，统一从现有入口调用；规则仍由唯一registry编译。没有重写整个服务，也没有修改真实分镜稿或历史首稿。

完整覆盖证据能防止漏项签证，不能证明审计员每条判断都正确。服务端无法看到未提交的聊天稿，也无法禁止模型调用别的宿主工具；宿主交付必须遵守回执核验。软件验收、线上部署、员工真实会话和实稿准确率须分别报告。本版不据此声称98%首稿可用率或一次审净。

发布前运行完整测试发现、运行时自测、HTTP/stdio及源码包校验。员工连接包须另行绑定正确员工连接并经真实会话确认，不分发管理员绑定。上线前暂停并确认没有正在写入的业务请求，再备份临时挂载的Library状态；新实例在开放服务前校验并完整恢复数据，已有冲突不得覆盖。随后核对配置、成员权限、签名密钥、项目指针和只读线上样例。发布实际结果由本次发布回执记录。
