# 剧情约束接入说明

本说明覆盖剧情方案、剧本、对白及其修改和审计。执行细则以技能中的 [剧情生产约束](../skills/shortdrama-storyboard/references/narrative-production-constraints.md) 为准；它完整承接原《模型生产约束：剧情版》的八类要求与六组反例。

文档写入、代码接入、软件验收、真实稿件质量和线上部署是不同状态。本文件不宣称已部署，不宣称真实首批已达到 98%，也不保证开放式创作零偏差。

## 八类要求如何落实

| 要求 | 生产或审查时的可执行动作 | 必须避免 |
|---|---|---|
| 1. 事实与授权 | 固定原文版本、用户目标、保留事实和允许变更；事实逐项关联位置，双向核对遗漏与误读 | 把抽取表当真相；把全部原文锁死；自行更改受保护关系 |
| 2. 场景计划 | 每场列时间、地点、在场者、知情来源、权限、道具持有、本场事件及末态，先查前置条件 | 作者知识直接变成人物知识；只查禁词不查含义 |
| 3. 跨批依赖 | 登记后场要用的关系、能力、财产或约定及其建立事件；改铺垫时同步改后文 | 计划当成既成事实；已删除取得事件却继续使用财物 |
| 4. 正文核对 | 保存完整候选后，双向核对实际正文与计划的主体、时间、状态、认知、数量和结果 | 只查配套状态表；把结构通过或作者自填 PASS 当语义通过 |
| 5. 依赖修正 | 按问题、根因、影响场景做修订；作废变化依赖上的旧审查结果；不受影响部分有据承接 | 无目的全文重写；只能改一句；通过改名、换目录清除失败 |
| 6. 审计者约束 | 固定适用规则；每条发现给版本、位置、冲突和依据；修正建议先接受同标准检查 | 把风格建议算错误；建议本身造错后反复处罚作者 |
| 7. 证据分层 | 分别报告已修正、结构通过、独立内容审查、正式冻结/签核 | 只读旧问题表就称完整复审；软件测试或哈希代替内容签核 |
| 8. 首批留痕 | 保存首个完整正文、内部重写和全部拒绝；预先固定单位及批次/每集分母 | 首次展示当首次生成；失败筛掉后宣称首批 98% |

事实表后来证明有错，允许纠正，但依赖它的计划和结论必须失效重查。用户授权的大改可以重建场景和后续依赖，不因保真规则被禁止。未决只阻塞确实依赖它的部分；非必要未知不应成为阻止一切创作的借口。

## 工具工作流与证据状态

剧情入口分别承担计划预检、尝试留痕、准确记录读取和正文审查：`preflight_narrative_plan`、`record_narrative_attempt`、`read_narrative_record`、`review_narrative_artifact`。剧本/对白经 `commit_project_artifact` 的 `narrative_candidate` 形式提交。精确参数及响应以技能参考中的接口节为准；运行版本未提供接口时，明确记为尚未执行，不回落到调用者自报“残留 0/新增 0”并宣称正式通过。

预检检查结构及明确关系，独立内容审查核对实际文本含义，两者不能相互替代。来源图和计划由模型建立时依然可能误解原文；程序把错误计划执行得一致，不等于故事正确。分镜动作、环境和四路投影的检查结果也不能直接用于普通剧情文件。

计划预检后还须由独立 `narrative_audit` 工单审查计划；正文只能生产其 `clean_scene_ids` 范围。必要未知和阻塞依赖保留，其余工作可继续。部分稿可以保存和限定范围审查，但不能把缺场整批标为通过。正文成功保存仍是 `draft`，独审以 `publication_id` 和实际文件哈希绑定；原文或计划版本变化后，旧结论失效。

v1 按故事发生时间顺序检查计划；倒叙或多时间线须显式分离故事事件顺序与呈现安排并获得相应审查，当前程序没有验证任意叙事重排，不能靠任意重排正文绕过门禁。剧情可改编通道不解除既有正式分镜的字面保真要求。

| 状态 | 可说明的内容 |
|---|---|
| 已修正 | 某版本已按指定问题更改，还需检查影响 |
| 结构/计划通过 | 已运行的对应检查通过，未知和未检查范围另列 |
| 独立内容审查完成 | 指定版本及预定范围已被独立阅读，给出缺陷和未决项 |
| 正式冻结或签核 | 已取得当前流程实际要求的发布/签核记录 |

合理差异与风格建议不扣正确率。新增规则单列适用范围；旧规则下新发现的实际遗漏仍应修正，并记录为先前漏检。没有因用户授权而扩大范围时，不擅自增加任务；已授权的跨章修正不设置任意次数帽。

## 六组验收对照

以下是验收要求，不能据此声称已经通过实测。

| 类别 | 合法对照 | 应发现的反例 |
|---|---|---|
| 血缘关系 | 不同表达保留同一关系；按授权另建新基线 | 幼亡无后胞弟被擅改成孟子平父亲 |
| 认知来源 | 据已见行为作有限怀疑；允许正常否定/引用 | 无来源知道另一世具体结果，或仅换词规避 |
| 地点连续 | 有归来事件后再出府 | 已离府、无返程或重设依据，却再次从府内出发 |
| 权限边界 | 用物件和职责明确三处差事 | 局部差事被写成未授予的全府权力 |
| 财物依赖 | 保留取得事件，或授权删线并同步改后文 | 未建立取得来源就使用见面礼或铺契 |
| 建议反复 | 建议先按同标准核对再执行 | 先建议、后不解释地把同表达判作作者新错 |

## 怎样报告质量

首个完整正文产生后，未展示给用户的内部修改也属于修订。计划整理、构建失败、首个完整正文、首次送审、修订后和最终签核分别记录；正文没形成的拒绝不虚构逐场分数，但不能从生产尝试统计中消失。

服务器只能保留实际提交的输入，无法强制观察未调用工具的聊天草稿或隐含思考。作者应在完整候选产生后立即提交原稿；如此前有未记录重写，应披露。一次服务器记录不自动证明模型只有一次生成。

正确率与直接可用率使用预先定义的内容单位，不使用软件方法数、规则数或拦截数。给出已证合格、确定缺陷、必要未知和总分母；未知不进入合格分子，未完成检查时不能冒称首批成绩已经确定。同一场多个问题按受影响场景并集计数，同时另报问题数。

目标“均 ≥98%”按整体及每集的正确率、直接可用率分别验收，使用未四舍五入的比例。不能用平均值遮住低分单集，不能临时拆空场抬分，也不能用修后结果替换原首稿。达到目标不豁免正式门禁或未完成的独立内容审查。

本轮文档与软件控制能证明接入范围和执行行为；是否提高真实首稿质量，需要保留失败尝试的真实正文样本及独立审查证据来回答。
