# 0.5.36 唯一模板与正式交付

本版保留既定 27 字段、十列母版和同源 R5 阅读结构。管理员及员工、ChatGPT
及 Codex 的新旧连接共用服务端规则；正式资格不依赖聊天记忆或安装端自报。

交付前调用 `read_project_artifact(section="formal_delivery")`。服务端重新读取
实际 XLSX，核对可见工作表、隐藏 canonical、登记文件哈希、当前模板及规则、
签名生产预检、精确版本的独立审计与交接链。只有全部通过才返回正式交付链接。
回执绑定项目、账号空间、文件 ID、文件字节、版本及五分钟有效期；接收端须在线
刷新回执并比较实际下载 SHA256。复制回执、改名或自行填写 PASS 不产生资格。

`production_batch` 只接受 JSON `{"storyboard_artifact_ids":["ART-..."]}`。
服务端重建经过核验的批次引用；不接受手写母版、替代格式或自报完成。批次完成
验证再次读取原文件与审计，过期或失效后不能沿用旧回执继续计数。

连接安装包排除本地生成器、校验器及导出脚本，替换为远程调用专用技能；依然
要求 `.app.json` 的真实认证连接。管理员开发源码包保留维护程序，不能作为员工
安装包发放。连接失效、规则未更新或不支持某段内容时停止正式生产，保留草稿。

安装描述采用当前校验器支持的 `.app.json` 字段，不再写入不受支持的
`required` 标记；旧描述中的 `required=true` 仅在打包时兼容归一化，源文件
不变。依赖约束由认证服务端及正式交付校验承担，不能把清单标记当成安全边界。

本服务不能物理禁止个人 ChatGPT/Codex 使用其他工具写文件。客户端交付和自动
续作控制器必须验证在线回执，才能保证这些外部文件无法计为正式分镜。本版不
声称给整个 ChatGPT/Codex 加了沙箱。员工使用必须确实由服务端识别为 Producer；
将管理员连接或源码维护权限发给员工不属于合格安装。

软件测试使用临时项目和合成内容。真实员工重新登录、两端安装和线上发布需要
分别记录验收证据；本说明不代表这些步骤已经完成，也不代表真实剧情质量通过。
