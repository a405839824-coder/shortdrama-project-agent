# 0.5.0 / R10.1紧凑母版升级协议

## 结论

0.5.0把“单镜正式母版”确定为唯一完整视频执行真值。模型只写一次镜头语义；服务端canonical只保存紧凑语义字段，Excel导出时才确定性生成正式母版和GPT关键帧投影。

新流程不再生成、保存或导出独立Seedance长字段、Seedance批次、`batches`对象、镜内`生成批次`或“生成批次”工作表，也不允许生产、审计、修复、缓存预热或后台任务重新扩写第二套镜头内容。

## R10.1的27字段canonical

每个镜头按以下顺序提交一次：

```text
镜头编号
时长
累计时长
功能类型
场景连续性ID
镜头类型
可见主体
空间站位描述
起始状态
机位
运镜方式
画面内容
音色
心理音轨
环境音效
环境动态
光影
光源来源
光源方向
色温倾向
生成限制
转场类型
切镜/转场提示词
参考图锚定
覆盖原文
原文依据类型
原文支撑句
```

`shot_uid、episode_id、scene_uid`等由服务端管理的身份元数据不属于模型写入的27字段。

### 字段合并规则

- `空间站位描述`：固定场景空间、人物相对位置、门窗/家具/道具层次及有源人物范围。
- `起始状态`：本镜开始瞬间的姿态、视线、手部、重心、呼吸、道具与上一镜动作进度。
- `画面内容`：唯一承载可见动作、表演、微表情、精确对白、六维发声细节、标点效果、听者反应、呼吸和镜尾状态。
- `音色`：继续作为独立字段保留，不并入其他标题。
- `光影、光源来源、光源方向、色温倾向`：四项全部必填；不能用一个笼统的“电影感”替代，也不能在同场景无依据跳变。

新写入禁止以下独立字段：`人物调度、动作与表演、台词、发声方式、标点语气、心理音轨属性、生成批次`。

## 单镜时间阶段

面向Seedance 2.5时，`画面内容`可以使用数字时间阶段，但不是强制项。若使用：

- 最多3段；
- 第一段从0开始；
- 每段按先后顺序连续；
- 不得留缺口、重叠、倒序或出现零时长阶段；
- 最后一段终点必须等于本镜声明时长。

例如3.6秒镜头可以写为：

```text
【0.0—0.8秒】人物收到刺激并转移视线。
【0.8—2.9秒】人物完成动作、表情与精确对白。
【2.9—3.6秒】听者延后反应，动作与呼吸收束到镜尾。
```

时间阶段只属于正式母版的视频执行信息。GPT关键帧投影必须移除数字时间、对白、口型和声音指令。

## 精确10列Excel

正式分镜工作表严格按以下顺序导出：

| 序号 | 列名 |
| ---: | --- |
| 1 | 分镜序号 |
| 2 | 时长 |
| 3 | 累计时长 |
| 4 | 功能类型/场景连续性ID |
| 5 | 正式分镜母版·字段合并 |
| 6 | GPT关键帧生成指令 |
| 7 | 参考图锚定 |
| 8 | 覆盖原文 |
| 9 | 原文依据类型 |
| 10 | 原文支撑句 |

`正式分镜母版·字段合并`包含单镜视频执行所需的完整事实，是唯一视频执行真值。`GPT关键帧生成指令`是同一canonical的导出时视觉投影，不是第二份模型创作，也不写回canonical。

导出器不得增加第11列Seedance内容；可见工作簿不得出现“生成批次”页。canonical sidecar可继续保存精确、可验证的紧凑语义和内部身份，但不保存两项导出投影。

## 停止重复生成

0.5.0的新路径遵循以下不变量：

1. 模型只提交27字段镜头，不提交正式母版、GPT投影或Seedance文本。
2. canonical只保存语义原子一次。
3. 导出器对最终canonical执行一次正式母版投影和一次GPT视觉投影。
4. 独立审计直接读取已提交canonical和导出物，不重新生成镜头或投影。
5. 修复只改变获授权的语义字段，再执行完整验证和一次新版本导出。
6. 新路线追踪应记录`legacy_generation_calls=0`、`seedance_batches_generated=0`和`model_authored_derived_chars=0`。

这项升级减少的是重复创作、重复传输、批次包装和后台扩写；完整生产校验、质量门禁、独立审计和人工签核不减少。

## 全量、增量与修复路由

| 变化类型 | 路由 |
| --- | --- |
| 首次正式生成或没有可靠基础canonical | `commit_storyboard` |
| 同一镜头身份、同一数量、边界与上游证据不变的局部修改 | production窗口使用`commit_storyboard_delta`，只传变化的27字段镜头和边界 |
| 对白文本、标点、顺序、分句或说话人发生变化 | 重建完整受影响场景或分集；同步更新原文映射、人物认知、保护对白、表演链与覆盖证据 |
| 插入、删除、移动、拆分、合并、重编号 | 重建完整受影响场景或分集并使用全量路线 |
| 原文映射、人物认知、集边界、场景拓扑、心理音轨或核心计划变化 | 重建完整受影响语义单元 |
| 独立审计证书确认的非结构字段 | repair窗口使用证书约束的`commit_storyboard_patch` |

Delta只减少重复生成和传输，不减少最终全表验证。审计和repair权限不得调用production delta绕过证书或边界检查。

## 窗口架构

正式项目长期保留两个独立窗口：

1. `production`：生成或修改，只能签发`production_preflight`与`production_to_audit` handoff。
2. `independent_audit`：只读消费生产handoff，独立复核八层质量并签发最终审计证书。

第三个`repair`窗口不是常驻窗口。只有同时满足以下条件才启用：

- 独立审计返回失败；
- 审计窗口签发了绑定精确artifact、canonical、问题和范围的修复包；
- 用户明确授权执行修复。

repair窗口不能签发最终通过；修复结果必须通过`repair_to_audit`返回原独立审计窗口终审。审计直接通过时不创建第三窗口。

## Legacy只读迁移

0.3.x/0.4.x文件和canonical仍可读取，但它们不是0.5.0的新写入格式：

- 审计历史artifact时先验证原始字节、原canonical和原指纹，不改写历史版本。
- 继续生产时创建新的R10.1 successor，旧人物调度确定性折叠到空间/起始状态；旧动作、表演、对白、发声和标点事实合并到`画面内容`；音色与四项光照保持可追踪。
- 旧Seedance列、独立提示词和批次只作为历史证据读取，不进入successor。
- 迁移只执行一次，并保留原UID或按旧结构确定性建立稳定UID；新版本不得再次导出旧字段。
- 无法从旧文件可靠得到`起始状态`或其他必需事实时，迁移必须阻断并要求补充，禁止自动编造。

旧版[UPGRADE_0.4.0.md](UPGRADE_0.4.0.md)仅作历史兼容参考；0.5.0生产以本文档和R10.1 Schema为准。

## 生产窗口提示词

> 使用短剧分镜项目管理与审计工具继续项目`PROJECT_ID`。本窗口角色为production。先验证0.5.0/R10.1状态与可复用artifact；禁止重复上传、解析或生成独立Seedance批次。仅生成授权范围的27字段镜头，符合边界时使用delta，否则重建完整受影响场景或分集。提交后停在production_preflight，禁止调用audit_storyboard。最终返回project_id、work_order_id、artifact_id、canonical_sha256、handoff_id、trace_id、cache_hit及未命中原因。

## 独立审计窗口提示词

> 使用短剧分镜项目管理与审计工具继续项目`PROJECT_ID`。本窗口角色为independent_audit，只读审计生产返回的精确artifact、canonical和handoff。禁止重新上传、生成、优化、修正或导出。缓存未命中时完成八层语义复核并提交semantic_audit。最终返回audit_certificate_id、production_trace_id、audit_trace_id、fast_path_evidence、cache_hit及未命中原因、问题数量与受影响镜头。

## 条件修复窗口提示词

> 仅在原独立审计失败、存在精确签名修复包且用户明确授权后创建repair工单。只修复包内范围；非结构字段可patch，结构/边界/认知/原文/编号/时长变化重建完整受影响场景或分集。禁止生成Seedance批次，禁止宣称最终通过；完成全表生产校验后交回原审计窗口。

## 性能验收边界

0.5.0可以确认的架构事实只有：模型不再重复撰写独立Seedance长文本，服务端不再包装或后台生成批次，canonical不再持久化导出投影，GPT只在导出时确定性投影。

不能仅凭这些架构事实承诺具体分钟数或压缩比例。端到端性能结论必须使用相同源文件、镜头范围、模型、服务档位、缓存条件与最终输出契约执行0.4.x/0.5.0 A/B，并同时记录：

- 端到端墙钟；
- 模型实际输出字符；
- canonical与XLSX字节；
- production和independent-audit两条服务端trace；
- 缓存命中/未命中原因；
- 最终问题数、残留数和新增问题数。

在同源A/B完成前，只能写“已从架构上消除重复生成”，不能写节省了多少分钟或百分比。
