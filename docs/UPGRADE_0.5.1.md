# 0.5.1 规则门禁与发布同步升级

0.5.1 是 0.5 紧凑 canonical 架构的规则与验证补丁。它不改变 27 字段 canonical、R10.1 Schema、R10-PG1 工作流或 `V16.3-148-R10-StableRuntime`；历史 0.5.0 artifact 仍按原始指纹保留且不就地改写。

## 升级目标

0.5.1 把已知的重复错误从自然语言提醒提升为生成后、导出前的硬门禁，并要求把历史失败样本固化为负向回归。发布要求至少覆盖：

- 逐镜 9:16 自包含契约；
- 转场双分隔符和相邻重复短句阻断；
- GPT 关键帧白名单投影与静态性检查；
- 跨镜代指、禁词、对白遗漏与说话人错位阻断；
- 单镜可见人数、主机位和核心动作阶段约束；
- 起始状态、结束状态和道具持有状态闭合；
- 对白、动作、反应和镜尾稳定的时长容量门禁；
- canonical、正式母版、GPT 投影和 XLSX 反向解析一致性；
- 独立审计签发前固定为 `PENDING_AUDIT`，禁止生产流程预写 PASS 或零问题。

## 版本绑定

0.5.1 发布必须使以下组件同时生效：

| 组件 | 要求 |
| --- | --- |
| 插件 manifest | `0.5.1` |
| MCP 服务版本 | `0.5.1` |
| 项目 compact master 版本 | `0.5.1` |
| Schema | `R10.1` |
| 工作流 | `R10-PG1` |
| 规则运行时 | `V16.3-148-R10-StableRuntime` |

插件 manifest、服务端 `__version__`、项目中枢策略或它们的测试断言不一致时，禁止打包和部署。规则、验证器或脚本改变后，旧的运行时测试证书不得复用；必须以新指纹重新执行完整自检。

## 发布前验收

任何一项失败都必须停止发布：

1. R10 黄金测试、严格提示词契约、公共场景、Agent 生命周期和全项目 Agent 测试全部通过。
2. 服务端自检、单元/集成测试、stdio 和 HTTP 冒烟测试全部通过。
3. 插件清单、技能清单、JSON/JSONL 和 Python 编译验证全部通过。
4. 所有历史失败样本必须被拒绝，对应修正样本必须通过。
5. 生成源码包后核对 `SHA256SUMS`，并确认包内不含凭据、虚拟环境、运行数据或历史 Git 目录。

## 部署和验收边界

本地修改、测试通过和源码包完成不等于云端已升级。只有在授权部署环境中更新服务、刷新 ChatGPT 连接，并在新对话中调用 `get_agent_status(full_self_test=true)` 后，才能声称完成同步。验收结果必须返回 0.5.1 版本、当前规则/验证器/脚本指纹以及由这组指纹签发的新证书。
