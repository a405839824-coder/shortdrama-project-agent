## Standard route

1. `get_agent_status(project_id?)`; verify window-neutral access and use the current authenticated window for the required next operation. A pending independent audit still selects the audit route and blocks a new production batch, but no window switch or permission recovery is required. Use continuation only when the server identifies a stored 0.5.13-or-earlier legacy window-bound work order.
2. If and only if status is `migration_required`, run `migrate_project_state(action="plan")`, inspect the compatibility report and before/after hashes, then run the explicitly authorized `migrate_project_state(action="execute")`; historical artifacts stay immutable. Obtain a valid executable status before continuing.
3. `create_project(project_name)` only when no matching project exists.
4. `begin_project_task(...)` for every request.
5. Before storyboard authorship, call `query_project_issues(...)` and bind its active prevention-profile hash to the task. Known patterns are identified across episodes, files, shots, batches, and versions; those fields are occurrence locations rather than dedup identity.
6. `import_source_file(...)` once per unchanged source fingerprint and `read_project_artifact(...)` for required content; automatic bulk is the default for long content, and `if_none_match` avoids re-reading unchanged content.
7. For novel/chapter conversion, finish complete reading and build the conditional `source_ingestion` evidence before planning shots.
8. `plan_change_request(...)` before script/storyboard add, modify, delete, replace, merge, split, or move.
9. Generate or rewrite within the locked scope. Before accepting each scene, compare its dialogue occurrence inventory against the server-derived source-dialogue authority manifest; exact text, punctuation, occurrence order and uniquely resolved speakers must close at 100%; legal cross-shot splits use occurrence identities and half-open character ranges that reconstruct the original exactly. After each complete scene, call `preflight_storyboard_draft(scope_kind="scene")`; a failed or ambiguous scene is repaired and preflighted again before downstream generation. Failure is persisted as a draft-preflight ledger event but creates no artifact, version, XLSX, projection, successor, or handoff.
10. For a first full draft, invalidated complete scene/episode, or any dialogue/speaker change, call `preflight_storyboard_draft(scope_kind="full")` on the exact final canonical. Only its signed, full-scope, commit-ready `draft_preflight_id` may authorize `commit_storyboard(..., draft_preflight_id=...)`. Use `commit_storyboard_delta(...)` only for an authorized same-identity/same-count visual or other non-cognitive execution change whose exact dialogue text, punctuation, order/segmentation, speaker identity, source mapping, cognition, and protected-dialogue evidence remain unchanged; supply exact base hashes, stable UIDs, target range, neighboring boundaries, refreshed shot-bound evidence, and only changed complete 27-field records. Psychological audio and any insertion/deletion/movement/split/merge/renumber or source/cognition/boundary/topology change also use the full route. Both commit routes save a compact canonical JSON/XLSX, production preflight, signed handoff, and honest server-only trace without claiming independent audit pass.
11. `commit_project_artifact(...)` for plans, scripts, dialogue, anchors, keyframes, BGM, voice, statistics, conversion, or production packages; do not use it to pre-generate a duplicate Seedance/batch narrative. Use `complete_task_validation(...)` for every non-storyboard deliverable.
12. From any authenticated window, call `audit_storyboard(...)` under distinct server independent-audit authority and the current `semantic-audit-v9-server-owned-obligation-coverage` contract. For repair return, invoke the exact original audit authority root. First read every current `audit_obligations` page for the artifact; submit actual observations and judgements using its returned schema and page transport. The server verifies full coverage and current dependency bindings together with machine findings. `coverage_pending` only acknowledges stored evidence. A layer PASS, a saved page or zero machine findings cannot replace the completed independent audit; audit never regenerates shots or projections.
13. `signoff_task(...)` only after the exact clean independent-audit certificate exists and the user explicitly approves or asks to reopen.

The first-draft production grade requires overall correctness and direct usability of at least 98%, both correctness and direct usability in every episode at least 98%, and new local issue rate of at most 2%, with zero hard errors, major issues, known-issue recurrences, or systemic duplicate patterns. This grade measures prevention quality and never relaxes a gate: full preflight becomes commit-ready only with no outstanding issue. Final independent audit requires all eight layers at 100%, with blocking, residual, and introduced counts all zero. These are acceptance targets, not proven model/plugin accuracy; actual performance requires untouched first drafts, fixed denominators and independent review evidence.

## Audit and repair route

- `audit_only`: audit the whole artifact once and report only the independent result; do not modify it.
- `audit_and_repair`: the original audit authority first issues an immutable certificate and problem package. Only then create the conditional repair authority; the user may request it from the same window. For certificate-confirmed non-structural shot fields, use `commit_storyboard_patch`; structural/boundary/cognition/source/order/timing/topology/core-plan repair uses the package-bound full `commit_storyboard` rebuild of the complete affected scene or episode. `commit_storyboard_delta` is production-authorized for user-directed changes, not a repair-authority shortcut. Every route creates a full new JSON/XLSX and runs all registered validators, G0–G13, THG-01–THG-17, complete N-1 adjacent-pair proof, voice-field proof, source-fact dialogue proof, T2I/lighting field proof, and multiline round-trip checks.
- A repaired version always returns through the signed `repair_to_audit` handoff to the same original audit authority root and audit cycle. Any authenticated window in the same namespace may invoke that exact root. Repair/preflight cannot sign itself off, and another audit root cannot consume it.
- A forced re-audit uses a fresh server-minted single-use successor handoff and distinct route/event traces; it never rewrites or reopens a consumed root. Every blocking issue must resolve to at least one canonical shot. Only the newest completed failed lineage's signed package may be consumed; an older package is superseded even if its signature remains valid.
- A modern certificate binds the exact ledger event SHA. Every successor binds its parent's certificate HMAC and event SHA, and storage verifies the bridge under the project lock. A legacy certificate without the event SHA cannot replay or authorize sign-off; it may only parent an explicit forced re-audit, and becomes historical only after that modern successor completes.
- A failed artifact cannot be relabelled PASS by submitting a new semantic report against the same file/source_version/artifact/canonical bindings. It must first produce a package-bound repaired artifact and fresh handoff, then return to the original auditor. Exact crash recovery may complete an event-only half-write only for the same normalized semantic/event/trace/fingerprint identity. The only case normalization is lowercasing a valid 64-hex caller `semantic_audit.canonical_sha256`; replaying that SHA in another hex case returns the same receipt without another successor/event/certificate/round, while every other field remains exact. The certificate must equal the complete deterministic certificate binding, not merely carry a valid HMAC; even a validly re-signed mismatch, certificate-only state, different semantic or stale lineage fails closed with zero authority/projection mutation. Repair-package replay accepts only a zero-downstream `issued` state or a fully closed `consumed` state with exact repair work order, successor/base CAS, metadata, return handoff and Hub projection. A consumed package may return to `issued` by compensation only when the original repair claim token and generation match, the fixed base successor transaction is already `aborted`, the signed handoff and Hub projection are both `rejected + aborted`, and there is no claim/consumption/audit-certificate or other independent-audit downstream reference. Any prepared/committed transaction, different claim, published/live handoff or audit downstream forbids release. `consuming`, forged terminal state, or a missing package with downstream evidence is corruption. Recovery runs under the same storage lock after rechecking latest lineage, exact certificate HMAC, zero downstream evidence and the fenced single-finisher claim; completed replay is otherwise read-only and cannot resurrect a package or return stale authority.
- The result is clean only when blocking errors, residual issues, and introduced issues are all zero.
- Reuse a prior independent result only when canonical, raw artifact, source, boundary, ruleset, validator and audit-class fingerprints all match. A production preflight never satisfies the first independent audit.
- Repeated findings prompt root-cause review. Select repair scope from causal evidence and invalidated dependencies; do not stop, force rebuilding, or reset the work-order history because of a default round count. Explicit user/host acceptance limits remain binding.

## Efficiency without lowering quality

- Delta changes reduce authored/transferred content, not validators: the model authors each semantic fact once in the 27-field compact record; actions, expressions, dialogue, lip-sync/timing, visible delivery cues, listener reaction and the natural action order; numeric production clocks are internal picture_timing annotations only exist in `画面内容`, while the complete fixed delivery specification exists only in `音色` and the four lighting fields remain explicit. The server computes episode-local cumulative timing/batch statistics, deterministically refreshes the N-1 adjacent-pair proof after state-row edits, and projects the R10-SPC-1 formal cell plus static GPT keyframe instruction only at export; it runs all registered validators, G0–G13, THG-01–THG-17 and the multiline XLSX round-trip, then hands the compact artifact to all eight audit layers.
- Production, audit, repair, cache warm-up, and background jobs must never pre-generate or persist Seedance text, `batches`, a Seedance column, or a generated-batch sheet. Legacy forms are read-only migration inputs; new versions never write retired fields back.
- Production owns canonical authorship and must correct a failed draft before commit. Deterministic code owns projection, validation, certificates, hashes, state transitions, and failed-draft learning. Independent audit owns only the read-only omission search and final semantic verdict; it is not a cleanup stage for known generation or template defects.
- Automatic 16,000-character bulk reads reduce long-source tool-call count while preserving exact-order, no-gap reconstruction.
- Tool traces cover MCP server time only. Report ChatGPT planning/generation as unmeasured unless the user explicitly requested the 0.5.3-or-newer no-API diagnostic and a complete five-checkpoint `mark_performance_stage` run exists. That diagnostic reports `tool_bracketed_chat`, not exact end-to-end time; never infer total chat duration from a fast server trace.

### Fast-safe call discipline

- An ordinary content task with a matching runtime-test certificate must not inspect plugin source, rerun bootstrap/golden/Agent suites, or rebuild system rules. `get_agent_status` verifies the certificate once.
- Use the plugin's authenticated project hub and issue ledger for ordinary content tasks. Do not materialize or rewrite the global Library hub/ledger unless explicitly requested for a shared-ledger task. A system/rule update alone does not authorize duplicate project facts; global archive aggregation references project event IDs.
- For an unchanged imported source, use its stored fingerprint and canonical evidence. Do not download or page through the same file again merely to restate production facts; a fingerprint mismatch or a genuinely missing semantic excerpt is the only reread trigger.
- A bounded production replacement normally needs `get_agent_status` → `begin_project_task` → `plan_change_request` → one `commit_storyboard_delta`. Add one automatic bulk read only when the changed semantic content is not already available. Full generation still uses the full route.
- A clean independent audit normally needs `get_agent_status` → one read-only audit work order → one `audit_storyboard` call against the signed handoff. On a cache miss, the audit chat reviews the canonical and supplies the eight-layer semantic evidence in that call while the service independently recomputes machine validators; on an exact cache hit the prior signed evidence is reused. The chat must not regenerate shots, repeat production preflight, or expand the complete workbook into prose.
- A failed audit may add the conditional repair chain only after authorization: one repair work order → one package-bound patch/full commit → one return audit by the original audit root. Do not pre-generate repair content; no extra user window is required.
- Keep intermediate chat updates brief and return IDs/hashes instead of echoing complete canonical rows. If the safe route needs extra reads or retries, record the concrete cache miss, fingerprint change, missing input, validator failure, or transport error that caused them.
- Do not call `mark_performance_stage` on this ordinary fast-safe route. It is an opt-in diagnostic wrapper, not a required production dependency.

## Cross-chat continuity

Continuity comes from the MCP data store, authenticated user namespace, stable `project_id`, and signed authority-root/epoch records; it does not come from reading inaccessible chat history. The MCP stores project state, versions, deliverables, audit events, recurrence, capability gaps, and active authority generations. In cloud mode, use persistent storage and OAuth so different users cannot share a namespace. Every trusted window in the same namespace has equal orchestration access; server work-order identities preserve production/audit/repair separation. Pending independent audit continues to block a new production batch until audit closes, while the current window may perform that audit directly.

## Brief user-facing audit format

- Clean: `审计通过｜阻塞错误0｜原问题残留0｜修改新增问题0`
- Failed: `审计未通过｜共N项` followed by short numbered items with shot IDs and one-sentence fixes.
- Blocked: one sentence naming the blocker and next action.
