# Bind a legacy formal workbook

Use this route only when plugin 0.5.25 advertises `controlled_workbook_migration.supported=true`, the user has explicitly approved migration, and the imported XLSX has one current ten-column formal sheet but no canonical sidecar. An Excel formal master exists even when its server canonical binding is missing; describe that distinction accurately.

1. Lock the imported `source:storyboard` artifact and raw SHA. Record a capability gap under a `capability_gap` work order whose targets include that artifact. Create an approved `rule_improvement + execute + explicit_execute` work order with targets exactly: one source `ART-...`, one `GAP-...`, `source_sha256:<raw SHA>`, `controlled_phase:legacy_workbook_canonical_migration`, and every episode ID in the workbook. Preserve source and protected scope. Existing approval in the conversation is sufficient.
2. Call `migrate_project_state(action="plan", target_version="workbook-canonical-v1", work_order_id=...)`. Check the exact source identity, all shot IDs, 27-field atom hash, multiline text, formula proof and deterministic transformation list. The parser reads original bytes, not extraction caches. It rejects ambiguous labels or scene IDs, unsupported/cross-episode formulas and stale cached values. No artifact or certificate is created.
3. If the returned transformations are only the approved deterministic formatting conversion, call the same route with `action="execute"`, `migration_id` and `expected_current_version` equal to the returned `plan_sha256`. The response supplies a dedicated production work order, not a PASS. A changed source, authority, policy or runtime requires a fresh plan. Repeating the exact request returns the same authority; a signed journal recovers an interrupted authorization. Do not broaden targets or relabel another operation to escape a failure.
4. Reconstruct the exact raw or approved prepared 27-field records. Complete actual source authority, replacement-plan mapping, protected occurrences and prevention evidence. Query current project issues and bind its active prevention profile. Do not generate fixture evidence or invent dialogue/coverage. Submit every scene and then the exact full canonical to `preflight_storyboard_draft` under the returned production work order. Migration does not authorize changing, adding or deleting shots. If content changes are needed, report the specific failed gates and use a separately authorized content route; never weaken validation.
5. Commit only with the signed full-scope commit-ready `draft_preflight_id`, exact original `source_artifact_id` and unchanged canonical. Use `commit_storyboard`, not delta or patch. The service saves a new canonical/workbook and `PENDING_AUDIT` handoff; the original workbook and its metadata remain unchanged. Only the new formal master and deterministic export are authoritative for the successor; retain the original workbook as immutable provenance.
6. Use the separate independent-audit authority to recompute all eight layers for the exact successor and submit actual semantic evidence. Only the returned signed independent certificate establishes its result. A migration receipt, runtime certificate or production preflight cannot stand in for that certificate. Preserve all unrelated pending handoffs and historical signatures. Export, save, read back and commit the complete project snapshot after mutation.

The 27 fields, ten export columns, 19 tools, source-dialogue authority and current timing policy remain unchanged. This route makes no measured-speech claim and does not restore the retired 2.8-unit budget.
