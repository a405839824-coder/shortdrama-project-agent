# R10-SPC-1 严格单镜提示词契约

本契约适用于短剧分镜全流程 Agent 后续新生成、重建、修正、审计和十列 Excel 导出。0.5.24统一当前规则注册源、逐发言事件计时与逐人/逐场景检查，保留27字段compact canonical、原文对白、人物认知、来源映射及生产/独立审计分工；不新增正式母版字段。规则定义以rule_registry.json为准，本文为执行写法参考。

## 1. 契约锁

新写入或新导出的正式分镜必须在 `source_lock` 中记录：

- `output_contract: R10-SPC-1`
- `target_model: Seedance 2.5`
- `aspect_ratio: 9:16`

画幅同时作为项目锁和单镜自包含执行契约：每镜 `生成限制`、正式母版和 GPT 关键帧投影都必须各明确写入一次 `9:16竖屏`。只禁止下列两条冗长旧固定短语：

- `9:16竖屏真人古装短剧截图质感`
- `9:16竖屏真人古装短剧单帧`

## 2. 镜头编号与累计时长

- 新写镜头显示编号统一为 `EP##-###`，例如 `EP05-001`。
- `shot_uid` 继续作为不可变内部身份；显示编号不得替代稳定 UID。
- `累计时长`按单集重置。每集首镜累计值等于本镜时长，每集末镜累计值等于该集总时长。
- 批次总时长等于全部镜头 `时长`之和，不等于最后一集末镜的集内累计值。

## 3. Excel 十列输出

正式工作簿恰好十列，顺序和列名固定为：

`分镜序号｜时长｜累计时长｜功能类型/场景连续性ID｜正式分镜母版｜GPT关键帧生成指令｜参考图锚定｜覆盖原文｜原文依据类型｜原文支撑句`

第五列表头只能写 `正式分镜母版`，不得恢复 `正式分镜母版·字段合并`。

## 4. 正式分镜母版的精确字段顺序

第五列每格必须从零上下文可执行，各段之间空一行，顺序固定为：

```text
镜头序号：EP05-001（3.0s；累计3.0s）

镜头类型：三人中近景，腰部以上｜可见主体：江氏、邹氏、许氏

空间站位描述：……

起始状态：……

机位：……

运镜方式：……

画面内容：【0.0—0.7秒】……【0.7—2.6秒】……【2.6—3.0秒】……

音色：

基础声线：二十余岁青年女声，中音区，声线偏薄而清亮，长期保持温润平稳的质感。

言语行为：带试探意味的问候。

当前表达：表面温和亲近，暗含确认自己是否迟到的试探。

发声方式：
音量：比日常交谈低一档，仅够近处对象听清。
语速与节奏：前半句自然，问句略放慢，不拖长字音。
呼吸：开口前轻吸气，句中不额外抢气。
停顿：在“大嫂”后的逗号处短停。
重音：明确落在本镜实际对白中的“没来晚”。
尾音：克制上抬。

禁止语气：撒娇、讨好、夸张惊慌。

心理音轨：无。

环境音效：……

环境动态：……

光影：……

光源来源：……

光源方向：……

色温倾向：……

生成限制：9:16竖屏；禁止额外配乐；……

转场类型：……

切镜/转场提示词：……
```

时长与累计时长始终保留一位小数和小写 `s`。不得缺字段、改序、合并光影四项或恢复退休字段。

## 5. `画面内容`三阶段硬格式

目标为 Seedance 2.5 时，每镜必须恰好三个阶段：

1. `【0.0—x.x秒】`：延续起始状态中的可见刺激、声音触发或人物第一反应。
2. `【x.x—y.y秒】`：本镜唯一核心动作；对白镜在全镜合法时间轴中完成动作、精确对白、口型、可见呼吸/停顿、重音期表演和听者反应，不强制只在中段说话；完整发声规格只写在`音色`固定子模板。
3. `【y.y—本镜时长秒】`：对白或动作落点、听者/主体镜尾反应、最终位置、视线、道具和切镜接点。

硬规则：

- 使用全角方括号 `【】`、中文长横 `—`、单位 `秒`，所有边界保留一位小数。
- 三段从 `0.0` 开始，连续、不重叠、正时长，末段精确闭合本镜时长。对白可从首段开始或延续末段；同一发言用出现身份与半开字符范围衔接，原句只写一次。显示取整后重新核对容量，不能掩盖真实超时。
- 容量统一调用timing_policy：逐发言、逐阶段，真实先后相加，可并行共用；停顿最长符号解析并按事件去重。无固定呼吸、听者反应或镜尾收费；确有先后与明确镜尾要求才独立计时。未标定估算与实测音轨/视听验收分别记录。
- 单镜只有一个主机位、一个核心动作阶段；阶段划分不得制造隐形切镜或第二事件。
- 不得把旧自然阶段、裸时间码 `0—1秒，` 或 1—2 段时间描述作为 R10-SPC-1 成品。

## 6. 对白、原文事实转化与表演

- `原文直接对白`的正文、标点、顺序和说话人必须逐字保持准确；允许用原句每次出现的稳定身份与半开字符范围合法拆镜，按顺序重拼原句，缺漏、重复、错序、换人或改标点失败。delta保持既定分段的限制不变，需要拆镜走完整受影响场景重建。
- 不以“有没有引号或说、问、劝等词”为判定中心，而以场景实际如何完成事件为准。文本即使全是叙述，只要其中存在问—答、劝—决、令—应、报—听、辩—核、证—判等交流闭环，或人物必须通过开口才能使另一人物知道、回答、执行、辩解、核验或作出决定，就属于`叙述性会话场景`或`混合会话场景`，必须还原人物对白和听者反应。
- 授权范围内每个叙述单元均须进入场景语义台账，明确选择`叙述性会话场景／混合会话场景／非会话叙述`，列出交流功能、交流双方和需要或不需要开口的依据。不得只扫描言语动词，也不得把应由语言完成的信息交换改成指账本、翻册、抬手、点头、对视等无声动作。
- 会话场景按交流节拍拆分原文事实：谁发问、谁陈述、谁辩解、谁举证、谁下令或作出决定。每个节拍转为`原文事实转化对白`并落入具体镜头；单镜容纳不下时增加镜头或重新分配低价值镜头，不得因时长不足删除对白环节。
- `原文直接对白`与`原文事实转化对白`必须分轨：前者进入`protected_dialogue`并执行THG-05逐字保护；后者不得冒充原文原句，必须进入`prevention_evidence.dialogue_adaptation_audit`，逐条绑定原文事实、说话人依据、事实原子、目标镜头、用户授权、`plot_change=false`、`new_plot_facts=[]`和`entailment_status=entailed_by_source`。
- 不是所有叙述都要改成对白。纯动作、环境、作者说明、人物未知内心或无需语言即可完整成立的证据状态，应分别处理为可视动作、环境、合法心理音轨或有理由的非对白处理；但授权范围内每个叙述单元都必须作出场景语义选择，独立审计逐单元复核，不能由生产侧写成“非会话”后直接放行。
- 否定性言语描述（如“没有开口”“不敢继续叫嚷”“不再解释”）不得被关键词命中机制误判为必须新增对白；审计必须先区分“实际发生的言语行为”与“被否定、停止或省略的言语行为”。
- 正式写法为 `角色说道：“完整对白。”`，不得继续使用旧标签 `【角色】“对白”`。
- `音色`是本镜唯一完整发声规格源。带对白镜必须按`基础声线 → 言语行为 → 当前表达 → 发声方式（音量、语速与节奏、呼吸、停顿、重音、尾音）→ 禁止语气`固定顺序填写；`发声方式`只是`音色`内部空值分组标题，不是恢复已删除的顶层字段。
- `基础声线`必须同时写清年龄感、音区、声音厚薄、明亮/低沉关系和长期稳定特征；`言语行为`写命令、质问、试探、安抚等可执行话语动作；`当前表达`用一句短句说明表层情绪和必要潜在意图，不写长篇心理分析。
- `音量、语速与节奏、呼吸、停顿`逐项具体；`重音`的每一个引号字/词都必须绑定对应说话人本次发言的实际位置，不能由一个真词掩盖另一个假词：原文直接对白取自原句，事实转化对白取自台账所列`adapted_text`；`尾音`明确选择上抬、下压、截断、发虚、落稳或短收；`禁止语气`只列本句最可能出现的2—4种错误表达。
- `画面内容`只保留声画同步所需的对白发生时点、口型、可见呼吸/停顿、重音期间不眨眼或动作配合以及听者反应，不复制整套音色子模板。标点、时间轴与音色规格必须一致。
- 无对白镜的`音色`固定写`无对白，不适用。`，不得伪造发声或口型。
- 可见开口人物写明 `口型与对白一致`，人物视线只落向剧情对象并 `不看镜头`。
- 面部清楚可见且持续约2秒以上时，`画面内容`必须按时间轴写出：视线起点 → 眼球轻微换焦/位移 → 眼球先动、头部随后轻跟或明确不跟 → 上/下眼睑松紧变化 → 具体眨眼时点或有剧情理由不眨眼 → 镜尾视线落点。不能只写“看向”“自然眨眼”或把眨眼泛写在`生成限制`。
- 眨眼优先放在开口前、自然换焦、句间换气、听完台词后的反应段或情绪回收；说话者在关键词、重音和决定性尾音期间明确不眨眼。3–5秒每人0–1次，>5–10秒每人1–2次。多人逐人写时点并错峰，不得同步、同时或同频眨眼。
- 高压对视、震惊、认出、警觉或重音可选择本镜/本段不眨眼，但必须写明理由，并同时保留眼球焦点调整、眼睑松紧和自然呼吸。禁止用“全程凝视、目光锁死、目光锁住、一直盯住、保持眼神不动、保持凝视”代替眼部动态；只有同时写入眼球微调和眼睑变化时才可保留压迫性凝视措辞。
- `生成限制`必须同时含：眼神自然聚焦、眼球换焦/位移、眼睑松紧、禁止无依据全程不眨眼、禁止僵直瞪视/目光僵死、禁止高频机械眨眼；多人镜再加禁止同步眨眼。
- 听者反应由刺激触发并错峰发生，不得只写所有人同时看向说话者。
- 删除“说话角色以明确音量……”等通用尾缀；不得在个性化音色后再追加“声音中等清晰、语速从容、关键词加重、尾音随句意收住”等统一中性模板。

## 7. 光影四项

四项各自回答不同问题，禁止互相替代：

- `光影`：明确主要受光主体、面部明暗关系、眼神/手部/关键道具可读性、高光和暗部材质。
- `光源来源`：列出场内真实存在且本镜实际采用的主光与弱补光来源；不得写二选一、候选光源或“视情况”。
- `光源方向`：写明光从画面哪一侧、何种高度、向何处斜落，暗侧如何补光及亮度怎样随纵深衰减。
- `色温倾向`：只写定性的暖冷关系、空间分布、肤色和衣料/木构/纸张等材质本色；不得写 Kelvin/K 数值，不得只写“暖中性”“电影感”或把整幅画面统一染黄、染红、染蓝。

同一场景从场景坐标核对真实光源身份/位置、逐个门窗状态、时段、暖冷结构和受光关系；允许等义改写及有空间依据的反打，真实变化须有事件依据，不对四字段整句作字符串相等要求。

光影选择顺序固定为：`时间 → 室内外/门窗 → 天气 → 场内真实主光与弱补光 → 方向和高度 → 人物/道具受光面 → 曝光与材质 → 叙事功能 → 同场连续性`。不得先写“幸福、浪漫、压迫、电影感”再凭空倒推出光源。

物理条件必须闭合：

- 夜晚、月夜、深夜不得使用清晨/午后日光；明确日景不得套青黑夜色、月光主光或无依据低照度。
- 室内日光必须由窗、门、天井等真实开口进入；烛、油灯、灯笼、火盆和火场主光必须在空间、起始状态、画面或锚点中真实存在或可明确推断。
- 发丝/肩线轮廓光只在后方、侧后或斜后光成立；正面/前侧光不能同时声称背缘轮廓。
- 单一烛火通常形成半明半暗面部；若写柔和均匀面光，必须同时说明夜空、浅墙、地面或纱幔的弱反射补光。
- 普通室内默认关闭halation；只有已建立的真实火焰、烛火或灯芯边缘允许极轻微局部晕光，不蔓延人脸背景。湿地、金属和釉面可有真实材质反射高光，不把它们当作室内halation例外。丁达尔光另需定向光与真实散射介质。
- 暗部通透是保持灰阶、材质和空间出口可读，不是把夜景均匀抬亮成白昼。
- 普通清洁室内以空气清澈和背景可辨为默认结果：使用前侧/侧面大面积漫射明暗，`光源方向`保留但不得写成穿插式可见光束；闭合窗户只写窗纸漫射透光，光影措辞不得擅自打开门窗。
- 普通室内正向禁用薄雾、烟雾缭绕、空气颗粒、奶雾、丁达尔光、体积光、光柱、柔焦、镜头扩散、高光晕染、强逆光、侧逆光和无依据轮廓光；负面限制中的“无/禁止”不得被审计误判为实际存在。
- 普通烟雾、细烟与英文halation同样进入门禁。局部烟气的具体来源须已存在于原文/场景，不得由光影字段自行添加；局部范围、不扩散/不遮挡、背景可辨须同时成立。有香炉或火场不豁免全屋雾化及全画面扩散。真实烛火/灯芯边缘可有极轻微局部halation，但不蔓延至人脸或背景。
- 火场、扬尘、爆炸、蒸汽或雨雾侵入等剧情事实允许局部介质；香炉/药炉只允许一缕局部烟气。均须明确不扩散、不遮挡、背景可辨且不泛白。
- 室外有源侧逆光可在清澈空气中成立，无需雾烟；只有空气雾感、可见光束和体积光额外需要真实散射介质及匹配天气时段。不得反向迁移为普通室内默认。

古装真人提示词先加载 `songyun_humanist_cinematography.md`；文生图、关键帧或光影选择再加载 `text_to_image_visual_prompt_decision.md`；夜间、黄昏后、黎明前、烛光或低照度场景另加 `ancient_night_cinematography.md`。具体晨光、红烛、朱红配色和焦段只在场景事实满足时使用。

## 8. GPT 关键帧生成指令

第六列只从同一 canonical 确定性投影视觉静帧，不是第二份视频执行文本：

- 首行固定写 `画幅：9:16竖屏`。
- 只从白名单字段投影：场景、可见主体、空间站位、起始状态中的一个静态姿态、机位、镜头类型、光影四项、环境的单一静态瞬间、材质、参考锚点和含 `9:16竖屏`的生成限制。
- 删除全部时间码、对白文字、口型、音量、语速、停顿、心理音轨、环境音效和其他音频指令。
- 删除运镜过程、切镜/转场指令和时间过程语；` 硬切、切至、转场、推镜、拉镜、跟镜、摇镜、由远及近、随后、接着、几秒后 ` 等动态词零命中。
- 不写本契约第1节列出的两条冗长旧 9:16 固定短语；干净的 `9:16竖屏` 必须保留。
- 面部可见时，静帧只读取`起始状态`中的确定瞬间：默认写“双眼自然睁开，不处于半眨眼或半闭眼瞬间”；只有原文或剧情明确闭眼、睡眠或昏迷时才允许闭眼。静帧不得描述眨眼过程。
- 不得新增剧情事实、人物、道具结论或与正式母版不一致的光源。
- 每个词组必须能被单张图直接看见或由摄影参数直接控制。`整个故事中最幸福的一刻、没有战争、没有离别、未来多年仍无法忘记、红色代表爱情/婚姻/希望`等作者旁白、未来信息和象征结论不得进入；先转成眼神、唇线、手部、距离、婚俗道具、环境活动、材质和可解释光色，无法转成可见证据的部分删除。
- 声音只能保留其可见来源：例如院中低声笑谈不进入静帧，可投影为院中筹宴人物处于自然交谈姿态；环境声音仍只留在正式母版。
- 连续动作必须选择一个可持续的确定瞬间；梦幻氛围在普通室内优先转成低饱和色彩、浅景深和可见表演，不使用柔焦、镜头扩散或高光晕染；室外或真实高亮满足前提时才允许克制局部扩散，不得转成仙侠神光或全画面雾化。

## 9. 校验与迁移

新生成、修正、导出和生产预检必须检查：

- EP 编号及单集累计时长；
- 十列表头和第五列名称；
- 正式母版首行、字段顺序与空行分段；
- 145/批次镜头等项目既定镜头数与时长闭合；
- 三阶段数量、标点、连续性和闭合；
- 对白保护、口型、完整眼部行为链、重音不眨、静帧眼睛状态和听者/多人眨眼错峰反应；
- 带对白镜`音色`固定子模板的标签、顺序、非空值、基础声线五项、言语行为、当前表达、六项发声方式、本镜对白重音、尾音方向和2—4项禁止语气；无对白镜固定不适用值；
- 原文事实转化对白逐单元台账，以及全量叙述单元的会话／混合会话／非会话分类、交流功能、参与者、开口必要性、原文事实蕴含、说话人依据、目标镜头、无新增剧情证明、100%覆盖率和有序集合SHA-256；
- `adjacent_continuity_audit`恰好覆盖成片顺序全部N−1个相邻镜头组；同场、跨场、跨集均不得跳过，pair顺序、七项状态、双方状态哈希和有序pair集合哈希一致；
- 光影四项完整、有源、无 Kelvin 和无二选一歧义；
- 文生图静态语义全部可见/可控，场景时间、空间、天气、主光、方向、受光效果和连续性相互支持；单帧不可证明叙事与无物理前提光效零命中；
- 普通室内空气清澈、背景结构清晰可辨、不泛白不雾化；雾烟、穿插光束、柔焦扩散、强逆光与门窗开合冲突零命中；剧情介质均局部受控；
- 每镜 `生成限制`、正式母版与 GPT 投影都各含一次干净的 `9:16竖屏`；
- GPT 投影的时间、对白、口型、音频、运镜过程、转场和时间过程语零残留；
- 两条冗长旧 9:16 固定短语零残留；
- 正式母版和 GPT 投影中 `BGM` 字面量零命中，需表达负面限制时统一写 `禁止额外配乐`。

旧成品保持只读，不覆盖原件。需要继续生产或修正时，创建 R10-SPC-1 新版本并完成受影响范围回归；不得把旧格式继续复制到新批次。

## 10. THG-01–17 导出前模板硬门禁

| THG-01 | 每镜生成限制、正式母版和 GPT 投影均明确写 `9:16竖屏` | `E-I2V-INDEP-002` |
| THG-02 | `切镜/转场提示词` 禁止 `；；`、`。。` 和标点归一化后的相邻重复句 | `E-DUPLICATE-GENERATION-001` |
| THG-03 | GPT 关键帧只从静态白名单字段投影，动态/转场/时间词零命中 | `E-JIMENG-TIMING-001` |

相邻镜头逐组连续性审计使用双重证据：生产canonical的`adjacent_continuity_audit`保存精确N−1对；独立审计`semantic-audit-v8-adjacent-continuity-structured-voice-conversation-t2i-indoor-lighting`的“空间连续”层必须按同序提交`pair:左镜->右镜`全集，并提交`reviewed_adjacent_pair_count=N−1`和该有序pair数组的SHA-256。少一对、重复、逆序、非相邻引用、哈希漂移或覆盖率低于100%均拒绝签发证书。空间连续问题若绑定pair，问题目标必须恰好是该pair左右两镜并保持左→右顺序。

同一独立审计中，“禁项与声音”层必须按canonical顺序为每个带对白镜提交`field:镜头编号.音色`证据；服务端同时重跑THG-15机器门禁，并在证书中绑定期望/已复核音色字段数、100%覆盖率和固定模板契约标识。少一镜、引用错误字段、音色结构不合格或机器报告含`E-VOICE-001`，均拒绝签发PASS。

`semantic-audit-v8-adjacent-continuity-structured-voice-conversation-t2i-indoor-lighting`还要求“源文对白”层按Source Ledger顺序为每个叙述单元提交`source-unit:单元ID`，独立判断其是否属于会话场景；并按canonical顺序为每个`原文事实转化对白`目标镜提交`field:镜头编号.画面内容`。任一单元漏审、误把会话判为非会话、缺失交流节拍、用无声动作替代、对白事实无法由原文推出，或把改编对白冒充原句，均拒绝签发PASS。

0.5.22独立审计契约升级为 `semantic-audit-v8-adjacent-continuity-structured-voice-conversation-t2i-indoor-lighting`。“机位可见性”层必须按canonical顺序为每镜依次提交 `field:镜头编号.光影`、`field:镜头编号.光源来源`、`field:镜头编号.光源方向`、`field:镜头编号.色温倾向` 四项证据，并核对普通室内空气清澈、背景可辨、门窗状态不被光线提示擅改；室内剧情烟雾须有来源且局部受控，室外氛围光须有天气/介质/真实光源前提。少一项、错序、字段引用不匹配，或机器门禁发现单帧不可见叙事、日夜冲突、无来源光、室内泛白雾化、穿插光束、无开口强逆光、全画面柔焦扩散、方向与轮廓光矛盾、无前提灯火反射/halation/丁达尔光，均拒绝签发PASS。

## 11. 0.5.5 草稿预检与发布门

本契约从“导出前检查”前移为“逐场景生成门禁”。正式生产必须按以下顺序执行：

1. `get_agent_status`；若返回 `migration_required`，先由授权的规则/版本工单计划并执行 `migrate_project_state`，重新取得可执行状态。
2. `query_project_issues` 读取跨批次问题模式和活动预防画像，并把画像哈希绑定到当前工单。
3. 每完成一个场景，立即调用 `preflight_storyboard_draft(scope_kind="scene")`。失败时只记录草稿问题，不创建 artifact、版本、XLSX、正式母版/GPT投影、successor 或 handoff；修复并重检后才能接受后续场景。
4. 全部场景干净后，对完整 canonical 调用 `preflight_storyboard_draft(scope_kind="full")`，取得与项目、工单、canonical、规则、验证器、生产工单服务器authority和预防画像绑定的签名 `draft_preflight_id`。
5. `commit_storyboard` 必须携带该证书；任一指纹变化、范围不是 full、证书非 commit-ready 或被跨工单或跨认证命名空间复用时都阻断；同用户另一窗口可接续同一服务器authority。
6. commit 后仍必须交由独立只读 authority 完成八层审计；生产预检和草稿预检都不能签发最终结论。

第一版完整草稿的质量结果不可被后续修补覆盖。A级要求：总体正确率≥98%、直接可用率≥98%、每集正确率≥96%、新增局部问题率≤2%，并且硬错=0、重大问题=0、已知问题复发=0、系统性重复=0。该阈值用于衡量生成器是否已把错误前置预防，不代表允许带问题交付；全量预检只有在未解决问题为0时才可签发 commit-ready 证书。

最终独立审计要求八层100%通过，阻塞、残留、修改新增问题均为0。职责不可混用：生产负责一次性创作 canonical 并在提交前修复；程序负责确定性投影、门禁、哈希/证书绑定和失败草稿记账；独立审计负责查漏并签发结论，不负责重写镜头或清理已知模板错误。
