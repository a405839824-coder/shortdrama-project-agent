# 0.5.46 分集规则与历史保全合同

本文件说明实际执行范围，不是首稿准确率或成片验收证明。注册源为 `rule_registry.json`；历史依据为 `historical_rule_baseline.json`，保留原始 10 份资料哈希、149 节索引及逐项迁移判断。

## 生成和交付

1. 先锁定原文、章节完整读入状态、分集边界、核心角色和适用制作配置。小说不能通过改成 `non_chapter` 关闭整章检查。
2. 在来源图的 `production_plan` 冻结所有决定；`episode_contract`、`borrow_ledger`、整章读入和源文范围也属于被绑定的决定。改动后必须重编译，不能沿用旧证明。
3. 生成前从 `shots[].ticks` 计算分集时长、单镜4秒及例外预算，失败不组装正文。实际声画、来源用途、机位和独审证据在编译及预检继续检查。
4. 当前新生产、重建、改写必须重放结构化计划。直接提交 canonical 不能绕过；旧稿审计/修复、经服务验签的旧工作簿迁移有明确的历史入口，不据此认证新首稿。
5. 片段预检只说明片段。`full/episode` 新生产需要声明完整集合同；整集不足 90 秒或超过 180 秒拦截。超过 180 秒的片段也不能用不完整声明逃过上限。重切分集必须保留原文，不加戏凑时长。
6. 正式母版仍为 27 字段、11 列导出；画面内容只容纳实际可见的动作、表演及精确对白，不显示制作时间码。内部事件时钟、声画容量和依赖证据保留。

## 字段形状

`project.prevention_evidence.episode_contract` 使用 `storyboard_schema.json` 中的严格对象定义：

```json
{
  "contract": "episode-production-contract-v1",
  "profile_id": "mother-episode-90-180-v1",
  "scope": "complete_episodes",
  "source_kind": "novel",
  "episodes": [{
    "episode_id": "EP01",
    "core_actor": "由原文与项目锁定的核心角色",
    "ending": "hook",
    "beat_events": [],
    "source_functions": []
  }]
}
```

这只是字段示例，空清单不能作为完整集交付。`scope` 可选 `fragment/complete_episodes/complete_series`；全剧还需要准确的 `series_episode_ids`。结尾可选 `hook/finale`，终局检查闭合，不强加新悬念。

`beat_events` 每项必须包含 `id/kind/shot_id/source_ids/delivery/start/end`；`delivery` 必含所属字段 `field`、实际原句 `quote`、真实执行身份 `event_ids`。时间使用真实事件的本镜秒数，必须与重放证据完全一致。实际在第8秒发声的对白不能填0秒作为开篇钩子；申报时间错误仍按真实执行计算指标并报错。类型为 `opening_hook/advance/ending_hook/closure/carryover`，出处栏不能代替实际交付，同一事件换句段或标签不能当新推进。

对白、客观旁白使用实际动作ID，分别属于画面内容、心理音轨。有来源使用绑定的可见动作及动作音效引用该动作ID。起始已写文字可引用 `state:<shot_id>:<paper_ref>`，字段为起始状态，时段来自该文字载体从初帧持续可见的实际窗口；字号可读性仍须独审。未建模的独立环境事件不计为已证实钩子。部分引句保守采用整个绑定事件时段，不能靠截词伪造更短交付。

`source_functions` 每项包含 `source_id/kind/shot_ids`；用途独立使用 `plot/montage/detail/description`，与原文 S/A/B/C 评级分开。细节另需 `micro_elements/baseline_seconds`。来源对应镜头必须与来源台账完全一致；基准时长与分类是否真实仍须独立核对。

## 执行点与边界

| 项目 | 软件执行 | 仍须独立核对 |
|---|---|---|
| 时长与范围 | 每集 90–180 秒；片段不认证整集；全剧准确集合 | 原文是否适合该边界，是否丢戏 |
| 开头面部 | 3 秒内锁定角色眼部窗口与实际计划重放 | 面部占画面 ≥30%、可辨程度、角色确实在场；眼部坐标不是脸部面积 |
| 开篇/推进/尾段 | 开头 5 秒、推进空档 ≤25 秒、末 12 秒钩子或闭合的交付锚点 | 钩子成立、推进不重复、连续道具动作不超过 22 秒；禁止用自报标签冒充语义 |
| 对白 | 实际角色发声区间合并去重，占比 ≥35%；另列各四分段时长及最长空档 | 语义自然、无声场景的合法性及空档理由；心理音轨不补角色对白 |
| 短镜 | 统计 `<1秒`、`<2秒`，不设最低配额；中近景+近景约60%为软目标 | 逐个短镜有源、有叙事功能，不能凑数 |
| 蒙太奇 | 镜数 ≤20%、时长 ≤15%、每源句最多 2 镜 | 分类真实、没有把比喻拍成新事件 |
| 描述段 | 每源句 ≤3 镜/8 秒，连续描述段 ≤整集15% | 实际是描述还是剧情动作 |
| 补足细节 | 每镜 ≤3 微元素，时长 ≤独立核对的基准1.5倍 | 基准和元素有源；不是每集最多3个来源 |
| 借后文 | 授权引用、来源所属集、目标集、后续真实来源及偿还声明必须完整一致 | 核对真实授权原件与后续边界；连三集/末三集细则按项目依据核对，服务端逐项绑定工单授权，独审核原始授权真实性 |

自然低对白、低密度或角色不在场发生冲突时，先重切边界；仍不成立就明确阻塞并说明来源冲突。生产者不能自报豁免、降低阈值或虚构动作。旧 60 秒下限、固定 105 秒和全剧 7200 秒不作为全局默认；旧工程特定要求须由管理员形成有范围、有依据的规则变更后再生产，当前没有自动豁免器。

未量化的面部面积、节拍意义、短镜功能、来源用途和借用真实性会生成 `episode-review:<hash>` 独审清单，绑定当前完整稿件、分集合同及实际字段。独审缺任一项、提交旧指纹或放入错误审计层均拒绝。它约束审计覆盖，不能证明审计模型的语义判断必然正确。

## 旧规则处理

- 取消固定三段画面时间码、强制眨眼、固定呼吸/反应/镜尾收费、每镜强凑四类细节。
- 动作复杂度经验分替换为实际动作资源、状态、可见性和并发检查；未经成片校准的分值不恢复为硬拆镜线。
- 固定机位 65%–75%、复杂运动 ≤5%、POV 反应及连续景别变化保留为风格建议；不为建议虚构表演或机械拆分。
- 修正次数只记录。清理工单、返回文案和活动模板的“三轮后停止/强制重建”；修复范围依据真实根因、差异和依赖失效。独立审计与授权边界继续执行。
- 历史基线验证保留规则 ID、触发和判定语义、阈值；不能因当前注册源删了一条就自动缩小基线。更改基线需明确迁移依据与正反例。

## 验证口径

`test_episode_rules.py` 是合成时间轴及边界测试，`test_v0534_rule_closure.py` 保留上一版入口检查；`test_v0535_production_contract.py` 使用完整合成集，覆盖当前生成、逐场/整集预检、提交、签名审计消费，以及拒绝后修正且保留首份请求。审计判断在测试中明确标为合成验收输入，不是对真实剧情的独立审查。旧版本的 1–2 镜协议夹具通过 `historical_entry_fixture.py` 单独隔离新生产入口要求，用于复核原有存储、签名、权限及修复；不得把这些历史夹具计作完整集新生产通过。

未知自由文本语义、实际表演质量、成片遮挡/音频和 98% 首批使用率没有因这些软件测试而获得证明。新规则能提前拦截支持范围内的错误，不能承诺任意题材或任意模型输出都达到 98%。


借用先在 `begin_project_task.borrow_permissions` 单独列明 `source_id/source_sha256/origin_episode/target_episode/next_source_id/authorization_basis`，仅明确执行的生产或修复工单受理。服务返回 `authorization_id`，再用于来源台账与借用台账；候选稿无法自行生成有效授权编号。授权属于当前项目，跨项目、改源句、改借用去向或改后续边界均不匹配。此入口只锁定内容范围，不允许生产者改全局规则。

单镜时长和例外、景别、站位、表演以及K列光影遵循 [shot_design_contract.md](shot_design_contract.md)。历史基线原文不改，授权变化记录于 `historical_rule_migrations.shot-design-0546`，不能让旧硬配额继续约束新生产。
